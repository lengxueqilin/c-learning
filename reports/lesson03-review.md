**② 第 6 条你用了 `long` + `%ld`**

```c

```

这就是第 2 课答疑里说的"**跨平台要用明确的宽度**"的实际应用。

## 六、💰 你的疑问 —— 完整解答

### ❓疑问 1：C 里的 `&` 和 `|` 跟 `&&` 和 `||` 是什么关系？Java 里那套规则在 C 里成立吗？

**先给结论：**

> **Java**：`&` 和 `|` 是**重载**的 —— 对整数是按位运算，对 `boolean` 是"**不短路的逻辑运算**"。
> **C**：`&` 和 `|` **永远只有"按位运算"一种含义**。
> **C 语言根本没有"不短路的逻辑运算符"。**

所以你那套 Java 经验，**第一行就成立不了**。

👉 **完整实验代码：[examples/07_qa_bitwise_vs_logical.c](../lessons/lesson03/examples/07_qa_bitwise_vs_logical.c)**
（我实测 0 错误 0 警告，你可以直接 `⌘⇧B` 跑）

#### 1. `&` 和 `|` 是"按位"运算，结果不是 0/1

```text
6 & 3  = 2    <- 按位与：110 & 011 = 010 = 2（结果不是 0/1！）
6 | 3  = 7    <- 按位或：110 | 011 = 111 = 7
6 && 3 = 1    <- 逻辑与：两边都非 0 -> 结果一定是 1
```

**看出区别了吗**：`&` 把两个数的**每一位**单独算，得到一个新的整数；
`&&` 只关心"是不是 0"，结果永远是 1 或 0。

#### 2. 决定性反例：`2 & 1` 和 `2 && 1` 结果**相反**

```text
2 = 10, 1 = 01

2 & 1  = 0    <- 按位与：10 & 01 = 00 = 0  —— 它说"假"
2 && 1 = 1    <- 逻辑与：两边都非 0           —— 它说"真"
```

**这才是它们不是一回事的铁证。**
你之前的经验之所以没暴露问题，是因为 `5 & 3` 和 `5 && 3` **恰好都是 1** —— 巧合骗了你。

#### 3. `&` 和 `|` **不短路**：两边永远都要算

```text
(0 && (calls = 99))  = 0,  calls = 0    <- && 短路，右边没执行
(0 &  (calls = 99))  = 0,  calls = 99   <- & 不短路，右边执行了！
```

**这一点最要命**，因为它会直接毁掉"防除以零"的写法：

```c
if (b != 0 && a / b > 2)    /* ✅ && 短路：b 是 0 时右边不执行，安全 */
if (b != 0 &  a / b > 2)    /* ❌ & 不短路：右边照样除 —— 除以零！ */
```

#### 4. `~` 和 `!` 同样不是一回事

```text
!0 = 1     <- 逻辑非：把 0 变成"真"
~0 = -1    <- 按位取反：每一位翻转，0 变成全 1（补码里就是 -1）
```

#### 5. 顺带回答你"示例里那个问题"的隐含疑问：短路是**语言保证**，不是编译器心情

C 标准（C17 §6.5.13 / §6.5.14）**明确规定**：

> `&&` 和 `||` 的左侧求值之后，如果已经能确定结果，右侧**不进行求值**。

所以你在讲义里看到的那三个"探针实验"（`calls` 那个），
**任何一个合规编译器都必须给你同样的结果** —— 那是规定，不是优化。

**反过来说**：C 里**没有**"一定要算完两边"的逻辑运算符。
如果你真的需要两边都执行，只能写成两句独立语句（或者用 `&` 配 0/1 的值，但那样不推荐）。

#### 6. Java vs C 对照表（建议存下来）

| 表达式 | Java | C |
| --- | --- | --- |
| `a & b`（a、b 是整数） | 按位与 | 按位与（**一样**） |
| `a & b`（a、b 是 boolean） | **不短路的逻辑与** | ❌ **不存在**（C 的 `&` 只按位） |
| `a && b` | 短路逻辑与 | 短路逻辑与（**一样**） |
| `a \| b`（boolean） | 不短路的逻辑或 | ❌ 不存在 |
| `!a` | 逻辑非 | 逻辑非（**一样**） |
| `~a` | 按位取反（整数） | 按位取反（**一样**） |

**为什么 C 不做重载？** 因为 C 诞生时**根本没有 `boolean` 类型**
（`_Bool` / `stdbool.h` 是 1999 年 C99 才加的），
`&` 和 `|` 从第一天起就是给整数做位运算的。C99 加了 `bool`，
但**没有**顺手给 `&`/`|` 增加"逻辑"含义 —— 因为那会**破坏已有的海量代码**。

#### 7. 最后一个坑：`&` 的优先级**比 `==` 还低**

```c
int r = x & 1 == 0;
```

clang 会当场警告：

```text
warning: & has lower precedence than ==; == will be evaluated first [-Wparentheses]
note: place parentheses around the '==' expression to silence this warning
note: place parentheses around the & expression to evaluate it first
```

它的真实含义是 `x & (1 == 0)` = `x & 0` = **恒为 0** —— 完全不是你想的"判断奇偶"。
**正确写法**：`(x & 1) == 0`，或者干脆用 `x % 2 == 0`（我们课上一直用的写法）。

> 顺便说：**位运算 `&` `|` `^` `~` `<<` `>>` 是个很大的话题**（做嵌入式、写协议、搞性能优化时天天用）。
> 它不在我们前 14 课的必修路线里，但如果你有兴趣，我可以**在后期加一节选修课**——
> 到时候你会发现：`x & 1` 判断奇偶、`x << 1` 等于乘 2、`x >> 1` 等于除 2，
> 这些技巧在处理硬件和二进制数据时非常有用。
