# 批改报告目录

每一课的批改结果放在这里，命名规则：

```
reports/lessonNN-review.md
```

例如第 1 课的批改报告是 `reports/lesson01-review.md`。

---

## 批改流程

1. 你完成作业后，对我说「**批改第 N 课**」；
2. 我读取 `lessons/lessonNN/homework/` 下的作业文件，以及 **`lessonNN-questions.md`（我的疑问）**；
3. 我实际**编译 + 运行**你的每一份代码（不是只看，而是真跑），记录真实的报错和输出；
4. 输出批改报告：**逐题评分 + 逐条点评 + 修改建议 + 值得表扬的地方**；
5. **新增**：报告最后一节 **「疑问解答」**，逐条回答 `lessonNN-questions.md` 里的问题；
   有代表性的疑问我会画图/写代码验证，而不是含糊带过；
6. 你按点评修改（如果需要），修改后可以再让我**复批**一次；
7. **达标（≥ 80 分）** 才进入下一课；未达标只补薄弱点，不推进新内容。

> **为什么把疑问单独做成文件**：学习中最亏的事，就是"当时没懂、后来又忘了问"。
> 写下来的那一刻，问题就已经解决了一半；我批改时也能顺手发现你的理解偏差。

---

## 评分标准（满分 100）

| 维度 | 分值 | 说明 |
| --- | --- | --- |
| **编译与运行** | 20 | 0 error、0 warning，程序能跑出正确结果 |
| **需求完成度** | 40 | 题目每条要求是否都做到了（含边界要求，如"正好 40 字符"） |
| **代码规范** | 20 | 缩进、命名、注释、文件头信息、无多余代码 |
| **理解程度** | 20 | 错误分析能否说清原因、填空是否用自己的话写对 |

**判定**

| 分数 | 结论 |
| --- | --- |
| 90–100 | 优秀，可以加速（可加拓展练习） |
| 80–89 | 达标，按计划进入下一课 |
| 60–79 | 基本达标但有关键漏洞，**先补练再进下一课** |
| < 60 | 不达标，重讲关键概念 + 重做作业 |

---

## 报告里我会明确写出

- **每一题**：编译是否通过、实测输出、与题目要求的差异；
- **问题清单**：按严重程度排序（会导致错误结果 > 不规范 > 风格建议）；
- **你写对了的地方**：具体指出，让你知道哪些习惯要保持；
- **疑问解答**：逐条回答 `lessonNN-questions.md` 里的问题（本课无疑问则标注"本课无疑问"）；
- **下一步**：达标 / 补练哪一点 / 需要重看讲义的哪一节。
