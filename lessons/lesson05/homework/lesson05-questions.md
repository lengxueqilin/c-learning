# 第 5 课 · 我的疑问（lesson05-questions.md）

> **这个文件是干嘛的**
> 学这一课的过程中，凡是**没听懂、想不通、觉得奇怪**的地方，随手写在这里。
> 不用写得漂亮，写"人话"就行 —— 你写得越具体，我回答得越准。
>
> **什么时候提交**
> 做完作业后对我说一句「**批改第 5 课**」，我会在批改报告之后**逐条回答**这里的疑问。
> 没有疑问也没关系：写一句"本课无疑问"即可。

---

## 写疑问的推荐格式

```markdown
## 疑问 N
- **在哪里**：（例如：lesson05-lecture.md 第 7 节 / task2 第 20 行 / 自己写的时候）
- **我不懂的是**：（用你自己的话说，说错也没关系）
- **我自己猜过**（可选）：（写了我能知道你的思路卡在哪一步）
- **想学到什么程度**：（只要会用 / 想彻底搞懂原理）
```

## 本课特别欢迎这几类疑问（第 5 课的"高危区"）

| 类型 | 可能的疑问 |
| --- | --- |
| **死循环排查** | "我怎么知道程序是死循环还是单纯在算很久？有没有办法看出它卡在哪一行？" |
| **`for` vs `while`** | "什么时候该用 `for`，什么时候该用 `while`？有没有硬性标准？" |
| **`continue` 的差异** | "为什么 `continue` 在 `for` 里安全、在 `while` 里可能死循环？本质区别在哪？" |
| **`do-while` 的存在意义** | "`do-while` 能做的事，`while` 不是都能做吗？为什么还要这个语法？" |
| **带标签的 break** | "Java 有 `break label;`，C 为什么没有？用标志变量不会很绕吗？" |
| **`while (1)` 的正当用法** | "讲义说 `while (1)` 是死循环，但我在别人的代码里经常看到它，那不是故意的吗？" |
| **嵌套循环的性能** | "外层 × 内层，那三层嵌套是不是就很慢了？多少层算太多？" |
| **`i++` vs `++i`** | "`for (int i = 0; i < n; i++)` 和 `++i` 版本有性能差别吗？" |
| **浮点循环** | "为什么浮点数不能当循环条件？我要遍历 0.1 到 1.0 怎么办？" |
| **输入结束** | "`task1` 要输入 0 才停，那如果用户不输 0 直接按 Control+D 呢？" |
| **作用域** | "为什么 `for` 里声明的变量，出了循环就没法用了？这不是很不方便吗？" |

## 疑问示例（**这是示例，不是真疑问，别照着抄**）

> ## 疑问 1
> - **在哪里**：lesson05-lecture.md 第 7.1 节，死循环
> - **我不懂的是**：讲义说死循环"编译器完全不警告"。可是编译器明明能做那么多检查，
>   为什么连"这个循环的变量在循环体里从来没变过"这种明显的事都看不出来？
> - **我自己猜过**：我猜是因为循环变量的更新可能藏在被调用的函数里（比如 `f(&i)` 改了 i），
>   编译器无法确定它到底变没变，所以干脆不警告。
> - **想学到什么程度**：想知道编译器在循环上到底能帮我检查什么、不能检查什么。

**为什么这个示例写得好**：它没有停在"为什么没警告"，而是**自己试着推理了编译器为什么做不到**。
这种"站在编译器角度想问题"的习惯，会让你以后写代码时对"哪些错误工具能帮我、哪些只能靠我自己"有清晰的认识。

### 小提示

不只有"看不懂"才算疑问，下面这些同样价值很高：

- **想验证理解**："`for (int i = 0; i < 5; i++)` 里，`i < 5` 一共判断了几次？"
- **怀疑写法**："我在循环里 `printf` 调试，打印一堆东西，有没有更好的办法？"
- **想提前知道**："第 6 课的函数，能不能把 `task3` 的拆位逻辑包起来复用？"
- **觉得奇怪**："为什么 `for` 的三个部分要用分号隔开，而不是逗号？"
