## 1. 五种算术运算符

| 运算符 | 名称 | 例子（`a=7, b=2`） | 结果 |
| --- | --- | --- | --- |
| `+` | 加 | `a + b` | 9 |
| `-` | 减 | `a - b` | 5 |
| `*` | 乘（**不是 `×`**） | `a * b` | 14 |
| `/` | 除 | `a / b` | **3**（不是 3.5！） |
| `%` | 取余（求余数） | `a % b` | **1** |

打开 [examples/01_arithmetic.c](examples/01_arithmetic.c) 跑一遍，**本机真实输出**：

```text
a = 7, b = 2

a + b = 9
a - b = 5
a * b = 14
a / b = 3      <- 整数除法，小数被砍掉（不是四舍五入）
a % b = 1      <- 取余：7 除以 2，商 3 余 1

a / b 的精确值 = 3.5000   <- 把 a 转成 double 再除

--- 负数除法与取余 ---
c = -7, b = 2
c / b  = -3     <- -3.5 向 0 取整  = -3
c % b  = -1     <- 余数符号跟随【被除数】(c 是负的)
c / -b = 3
c % -b = -1     <- 余数符号依然跟随被除数
7 % -3 = 1      <- 被除数是正的，所以余数为正

规律一句话：商向 0 取整，余数的符号跟被除数走。
```

### 三个必须记牢的点

**① 整数除法规则（第 2 课讲过，这里正式化）**

```c
7 / 2      = 3        /* 整数 / 整数 = 整数，小数直接砍掉 */
7 / 2.0    = 3.5      /* 有一个是小数 → 结果就是小数 */
(double)7 / 2 = 3.5   /* 强制转换，同样效果（推荐） */
```

**② 取余 `%` 只能是整数**

```c
7 % 2      = 1        /* ✅ */
10.0 % 3   /* ❌ 编译报错：invalid operands to binary expression */
```

**③ 负数规则（C99 起统一）**：**商向 0 取整，余数的符号跟被除数走**。

| 表达式 | 数学上的值 | C 的结果 | 说明 |
| --- | --- | --- | --- |
| `-7 / 2` | −3.5 | **−3** | 向 0 取整（不是向下取整到 −4） |
| `-7 % 2` | —— | **−1** | 符号跟**被除数**（−7 是负的） |
| `7 % -3` | —— | **1** | 被除数是正的，所以余数为正 |

> 为什么不用负数取余？**因为容易记错。** 工程上遇到负数取余，先想清楚你要的到底是什么。

## 2. `%` 取余的四大用途（本课最实用的一节）

`%` 是新手最容易低估的运算符。打开 [examples/02_modulo.c](examples/02_modulo.c)：

### 用途 1：判断整除 / 奇偶

```text
=== 用途 1：判断奇偶 / 整除 ===
n = 17
n % 2 = 1          <- 余 0 是偶数，余 1 是奇数
n 是偶数吗？ 0      <- 表达式 n % 2 == 0 的结果（0 假 / 1 真）
n 能被 3 整除吗？ 0
记住：a 能被 b 整除  <=>  a % b == 0
```

**"a 能被 b 整除" 和 "a % b == 0" 是同一件事** —— 这句话请刻进脑子，
以后判断闰年、判断质数、分组，全靠它。

### 用途 2：把一个数的每一位拆出来（经典必会）

```text
=== 用途 2：把 483 的每一位拆出来 ===
个位 = num % 10        = 3
十位 = num / 10 % 10   = 8
百位 = num / 100 % 10  = 4
各位数字之和 = 15

拆位原理：先 / 10 砍掉尾巴，再 % 10 取出新的尾巴
  483 / 10 = 48,  再 % 10 = 8
```

**原理拆开看（这三行是本课最值钱的推导）：**

```text
483 / 10  = 48      ← 整数除法，把最后一位【砍掉】
48  % 10  = 8       ← 取余 10，把最后一位【取出来】

两步配合，就能从右往左一位一位地取：
  取个位：483 % 10          = 3
  取十位：(483 / 10) % 10   = 8
  取百位：(483 / 100) % 10  = 4
```

> ⚠️ **顺序不能反**：写成 `num % 10 / 10` 就完全错了（先取出个位 3，再除以 10 得 0）。
> **口诀：先 `/` 砍掉尾巴，再 `%` 取出新尾巴。**

### 用途 3：把大范围的值映射到小范围

```text
=== 用途 3：映射 / 分组 ===
47 秒属于第 4 号区间（每 10 秒一档，从 0 号开始编号）
47 秒在这 10 秒里的第 7 秒（用 47 % 10 取出来）
```

`47 / 10 = 4` 告诉你"在第几档"，`47 % 10 = 7` 告诉你"在这一档里的第几个"。
**任何"分组 / 循环 / 取模映射"的场景，都是这个模式。**

### 用途 4：进制转换的零件（第 5 课组装）

```text
=== 用途 4：进制转换（第 5 课学循环后组装成完整程序）===
13 转成二进制，每次 % 2 得到一位：
  13 % 2 = 1   13 / 2 = 6
   6 % 2 = 0     6 / 2 = 3
   3 % 2 = 1     3 / 2 = 1
  （把余数倒过来读：1101 —— 正是 13 的二进制）
```

看到了吗？**`% 2` 取一位、`/ 2` 砍掉一位** —— 和第 2 条拆十进制完全同构！
只是现在是**手工重复了 3 次**。第 5 课学了循环，你就能让机器自己重复到 0 为止。

## 3. 自增自减与复合赋值

打开 [examples/03_incdec.c](examples/03_incdec.c)：

### 3.1 单独使用时：`i++` 和 `++i` 一模一样

```text
=== 单独使用时：一模一样 ===
i = 5; i++;  结果 i = 6
i = 5; ++i;  结果 i = 6
i = 5; i--;  结果 i = 4
i = 5; --i;  结果 i = 4
```

### 3.2 混在表达式里时：完全不同

```text
=== 混在表达式里：完全不同（危险区）===
a = 5; r = a++;   ->  r = 5, a = 6
a = 5; r = ++a;   ->  r = 6, a = 6
```

| 写法 | 名字 | 顺序 | 结果 |
| --- | --- | --- | --- |
| `r = a++;` | **后缀**（postfix） | **先用后加**：先把 5 交给 r，a 再变 6 | r=5, a=6 |
| `r = ++a;` | **前缀**（prefix） | **先加后用**：a 先变 6，再把 6 交给 r | r=6, a=6 |

**记忆法：`++` 写在前面 = 先加再用；写在后面 = 先用再加。**

### 3.3 ⚠️ 一条纪律（请务必遵守）

```c
i++;                          /* ✅ 好：单独一行，谁都看得懂 */
printf("%d %d\n", i++, i);    /* ❌ 灾难：参数求值顺序在 C 里是未指定的！ */
a = a++ + ++a;                /* ❌ 灾难：同一变量被多次修改 = 未定义行为 */
```

> **纪律：自增自减永远单独一行使用，绝不塞进表达式里。**
> 上面两种写法**不是"结果不确定"，而是"代码本身就是错的"**（未定义行为）。
> 你觉得可以省字符，代价是三天后的你查不出 bug。

### 3.4 复合赋值：省事又清楚

```text
=== 复合赋值 ===
初始 x = 10
x += 5  ->  15
x -= 3  ->  12
x *= 2  ->  24
x /= 4  ->  6   <- 注意还是整数除法
x %= 4  ->  2   <- 取余赋值

累加器：sum 依次加 1、2、3 -> 6   （第 5 课循环就靠它求和）
```

| 简写 | 等价于 | 读作 |
| --- | --- | --- |
| `x += 5` | `x = x + 5` | "把 x 加上 5" |
| `x -= 3` | `x = x - 3` | |
| `x *= 2` | `x = x * 2` | |
| `x /= 4` | `x = x / 4` | |
| `x %= 4` | `x = x % 4` | |
| `x++` | `x = x + 1` / `x += 1` | 三者等价 |

**`sum += ...` 这种"累加"写法，是第 5 课循环求和的核心动作**，现在就练熟。

## 4. 关系运算符：结果是 0 或 1

打开 [examples/04_logic.c](examples/04_logic.c)：

```text
=== 关系运算符：结果只有 0 或 1 ===
a = 5, b = 3
a >  b  ->  1
a <  b  ->  0
a >= b  ->  1
a <= b  ->  0
a == b  ->  0     <- 判断相等要写两个等号！
a != b  ->  1     <- != 读作"不等于"
```

| 运算符 | 含义 | 易错点 |
| --- | --- | --- |
| `>` `<` `>=` `<=` | 大小比较 | `>=` 是"大于**或等于**"，别写成 `=>` |
| `==` | **判断相等** | ⚠️ **必须两个等号**！一个等号是赋值 |
| `!=` | 不等于 | 是 `!` 加 `=`，不是 `<>`（那是别的语言） |

**`==` 和 `=` 的区别是本课头号杀手**（详见第 8 节）。

### C 语言里的"真"是什么

```text
=== C 语言里"真"是什么 ===
0 是假，非 0 都是真（负数也算真！）
!0 = 1      !5 = 0      !(-3) = 0
t && t = 1    t && f = 0    f || f = 0    f || neg = 1
```

| 概念 | C 的规则 |
| --- | --- |
| 假 | **只有 0** 是假 |
| 真 | **一切非 0** 都是真（`5` 是真、`-3` 也是真） |
| 比较运算的结果 | 真输出 `1`，假输出 `0`（标准保证是 1 和 0） |

> 💡 这就是为什么 `if` 可以直接写 `if (n % 2)` —— 余数是 1 就是真。不过为了可读性，
> 我们**还是写清楚** `if (n % 2 != 0)`。清楚比聪明重要。

## 5. 逻辑运算符与短路求值（本课重点）

| 运算符 | 名称 | 什么时候为真 |
| --- | --- | --- |
| `&&` | 逻辑与（and） | **两边都真**才真 |
| `\|\|` | 逻辑或（or） | **有一边真**就真 |
| `!` | 逻辑非（not） | 真变假，假变真 |

### 5.1 短路求值：左边能定结果，右边就不执行

```text
=== 短路求值（重要！）===
规则：左边已经能决定结果时，右边【根本不执行】

(0 && (calls = 99))  = 0,  calls = 0   <- 右边没执行
(1 || (calls = 99))  = 1,  calls = 0   <- 右边没执行
(1 && (calls = 99))  = 1,  calls = 99  <- 这次执行了
```

**怎么读这段实验**：我用 `calls` 当"探针"（右边执行了就会变成 99）。

| 表达式 | 推理 | 右边 |
| --- | --- | --- |
| `0 && (...)` | 左边是假 → `&&` 一定是假 → **没必要看右边** | 跳过 ✅ |
| `1 \|\| (...)` | 左边是真 → `\|\|` 一定是真 → **没必要看右边** | 跳过 ✅ |
| `1 && (...)` | 左边是真 → 还得看右边才知道结果 | 执行了 |

**为什么要这样设计？两个理由：**

1. **效率**：能不算就不算；
2. **安全**（更重要）：

```c
if (b != 0 && a / b > 2)     /* b 是 0 时，右边根本不会执行，避免除以零！ */
```

**这句话现在就记住**：短路求值是 C 程序员防"除以零"的标准写法。
（`if` 我们第 4 课才学，但原理你已经懂了。）

### 5.2 实战：闰年判断，一个表达式搞定

```text
=== 实战：闰年判断 ===
规则：能被 4 整除，但不能被 100 整除；或者能被 400 整除

2000 是闰年吗？ 1
1900 是闰年吗？ 0
2024 是闰年吗？ 1
2023 是闰年吗？ 0
```

表达式长这样：

```c
(2000 % 4 == 0 && 2000 % 100 != 0) || 2000 % 400 == 0
```

**逐段读**：

```text
(能被 4 整除  并且  不能被 100 整除)  或者  (能被 400 整除)
└────────── 这是一组，先算 ─────────┘       └── 再和它做"或" ──┘
```

**1900 是特例**：它能被 4 整除、也能被 100 整除 → 前半组是假；又不能被 400 整除 → 整体为假 ✅
**2000 也是特例**：虽然能被 100 整除，但能被 400 整除 → 整体为真 ✅

> 这个"百年不闰、四百年又闰"的规则，是逻辑运算最经典的练习。
> **作业 3 就让你自己写它。**

## 6. 优先级与结合性

打开 [examples/05_precedence_cast.c](examples/05_precedence_cast.c)：

```text
=== 优先级：先乘除后加减 ===
1 + 2 * 3     = 7
(1 + 2) * 3   = 9
10 - 4 - 3    = 3    <- 同级左结合：(10-4)-3
100 / 10 / 2  = 5    <- 同级左结合：(100/10)/2

=== 算术 > 关系 > 逻辑 ===
1 + 2 > 2       = 1   <- 等价于 (1+2) > 2
1 > 2 == 0      = 1   <- 等价于 (1>2) == 0
2 > 1 && 3 > 2  = 1   <- 等价于 (2>1) && (3>2)
!0 + 1          = 2   <- 等价于 (!0) + 1

=== 赋值：优先级最低 + 右结合 ===
a = b = c = 5;  ->  a=5 b=5 c=5   <- 从右往左赋值
```

### 优先级表（本课够用版，从高到低）

| 级别 | 运算符 | 说明 |
| --- | --- | --- |
| 1（最高） | `()` | **括号** |
| 2 | `!` `++` `--` `(类型)` 负号 | 单目运算符 |
| 3 | `*` `/` `%` | 先乘除模 |
| 4 | `+` `-` | 后加减 |
| 5 | `>` `<` `>=` `<=` | 关系 |
| 6 | `==` `!=` | 相等性 |
| 7 | `&&` | 逻辑与 |
| 8 | `\|\|` | 逻辑或 |
| 9（最低） | `=` `+=` `-=` … | 赋值（**右结合**） |

**口诀：单目 > 算术 > 关系 > 逻辑与 > 逻辑或 > 赋值**

### 一条比优先级更重要的工程建议

> **拿不准就加括号。括号不要钱，bug 很贵。**

```c
int ok = year % 4 == 0 && year % 100 != 0 || year % 400 == 0;      /* 能跑，但读起来费劲 */
int ok = ((year % 4 == 0) && (year % 100 != 0)) || (year % 400 == 0);  /* ✅ 一眼看懂 */
```

第二行我甚至**不依赖优先级**也能得到正确结果 —— 这才是好代码。

## 7. 类型转换

### 7.1 隐式转换：编译器自动帮你提升

```text
隐式转换：3 / 2.0          = 1.50   <- int 被自动提升为 double
```

规则（够用的版本）：**两个不同类型运算时，范围小的会被"提升"成范围大的**
（`int` → `double`，`char` → `int`……）。

### 7.2 强制转换：你自己说了算

```text
强制转换：(double)3 / 2    = 1.50   <- 推荐写法
括号范围：(double)(3 / 2)  = 1.00   <- 先整除再转，白转了！
```

**⚠️ 这两行的区别是本课最经典的陷阱之一：**

| 写法 | 执行顺序 | 结果 |
| --- | --- | --- |
| `(double)3 / 2` | 先把 `3` 转成 `3.0`，再 `3.0 / 2` | **1.5** ✅ |
| `(double)(3 / 2)` | 先算括号里 `3 / 2 = 1`，再转成 `1.0` | **1.0** ❌ |

**记忆法：`(类型)` 这个"帽子"只戴在紧挨着的那一个操作数上。**
所以**想要小数，就要在"做除法之前"就把它变成小数**。

> 第 2 课作业里你写的 `(double)a / b` 就是正确写法 —— 而且比我示范的 `a / 2.0` 更好，
> 因为除数是变量，你只能转换被除数。**这一点你当时就做对了。**

### 7.3 小数转整数：直接砍掉（不是四舍五入）

```text
小数转整数：直接砍掉小数部分（向 0 取整，不是四舍五入）
(int)3.99  = 3
(int)-3.99 = -3    <- 负数也是向 0 取整
(int)2.5   = 2    <- 不是 3！
```

**"向 0 取整"= 把小数点后面直接删掉**。想四舍五入要自己写：

```c
int rounded = (int)(x + 0.5);      /* 正数的四舍五入（负数要另外处理） */
```

## 8. ⚠️ 三个"零警告但结果错"的陷阱（本课收尾重点）

这三条都是**编译器一声不吭、程序正常结束、答案完全是错的** ——
它们比前两课的所有报错都危险。

### 8.1 把 `==` 写成 `=`（头号杀手）

**实测（零警告，退出码 0）：**

```text
x 等于 5 吗？ 5
x = 5
```

| 你的意图 | 实际发生 |
| --- | --- |
| `x == 5`：判断，应该输出 `1` | `x = 5`：赋值，表达式值是 **5**，而且 **x 被悄悄改掉了** |

**为什么没警告？** 因为在 `printf` 参数里用赋值表达式是**合法语法**。
只有当比较结果被完全丢弃时（写成单独一句 `a == b;`），clang 才会警告：

```text
p5.c:2:38: warning: equality comparison result unused [-Wunused-comparison]
    2 | int main(void) { int a = 7, b = 2; a == b; return 0; }
      |                                    ~~^~~~
      + note: use '=' to turn this equality comparison into an assignment
```

**防身三招**：① 判断相等念出来"等于等于"；② 比较结果一定用掉；
③ 看到 `-Wunused-comparison` 先想"我是不是想写 `=`"。

### 8.2 有符号整数溢出（未定义行为 UB）

**实测（零警告，退出码 0）：**

```text
big + 1 = -2147483648
```

`int` 最大是 `2147483647`（`INT_MAX`），再加 1 就"绕"成了最小值。

**C 标准规定：有符号整数溢出是"未定义行为"（UB, Undefined Behavior）。**
意思是**编译器爱怎么处理都行** —— 你不该依赖任何具体结果。

用 **UBSan** 抓它（`-fsanitize=undefined`）：

```text
runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior p4.c:2:57
```

> 📌 **这就是第 2 课你思考题里那个问题的正式答案**：
> 你用 `a = a + b; b = a - b; a = a - b;` 交换两个数，思路**完全正确**、结果也对，
> 但中间那步 `a + b` 一旦超过 `INT_MAX` 就触发 UB。
> **结论：交换永远用临时变量。** 你现在知道为什么了。

### 8.3 除以零：在你的电脑上**居然不崩溃**

这是本课最反直觉的实测发现。**零警告。运行结果：**

```text
7 / 0 = 0
7 % 0 = 7
[退出码 0]
```

| 你可能以为 | 本机真相 |
| --- | --- |
| 除以零会崩溃 | **Apple Silicon（arm64）的除法指令遇到除数 0，直接返回 0，不崩溃、不报错** |

**为什么？** 这是 ARM 的硬件行为。在 Intel Mac / Linux（x86）上，同样的代码通常会收到
`SIGFPE` 信号而**崩溃**。

**哪个更糟？不崩溃更糟！** 崩溃至少你知道出事了；这里是**悄悄给你一个错误答案**。

用 UBSan 抓它：

```text
runtime error: division by zero
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior div0.c:6:30
```

> 🎓 **这一节值得单独记住**：同一段 UB 代码，在 Intel 上崩溃、在 Apple Silicon 上静默算错。
> **所以"在我电脑上是对的"从来不是理由。**
> **正确做法：除法之前先确认除数不为 0** —— 这正是第 4 课 `if` 要解决的第一个实际问题。

### 8.4 附：有符号和无符号混着比（`-Wsign-compare`）

**实测：**

```text
-1 < 1u 的结果 = 0   <- 你以为 1，其实是 0！
因为 -1 被转成了无符号数：4294967295
```

| 原因 | `int` 和 `unsigned int` 混合运算时，`int` 会被转成无符号；`-1` 就变成了 `4294967295` |
| --- | --- |
| **后果** | 数学上 `-1 < 1` 成立，程序里却**不成立** |
| **怎么改** | 别混着比；看到 `-Wsign-compare` 警告**不要忽略** |
| **最容易踩的地方** | 和 `sizeof` 比较（`sizeof` 是无符号的 `size_t`） |

## 9. 小测验（先自己想，再展开答案）

**Q1.** `17 / 5`、`17 % 5`、`17 / 5.0` 分别是多少？

**Q2.** 用一行表达式判断"n 能被 7 整除"，怎么写？

**Q3.** 想取出 `num = 483` 的**十位数字 8**，为什么是 `num / 10 % 10`，而不是 `num % 10 / 10`？

**Q4.** `int x = 5; printf("%d\n", x = 5);` 屏幕上输出什么？这句话有什么危险？

**Q5.** 执行 `int n = 0; int r = (0 && (n = 99));` 之后，`n` 是多少？为什么？

**Q6.** `(double)3 / 2` 和 `(double)(3 / 2)` 的结果分别是多少？为什么不一样？

**Q7.** `int big = 2147483647; int bigger = big + 1;` 这样写，编译器会报错吗？结果是什么？

<details>
<summary>👉 点这里展开答案与解析</summary>

**A1.** `17 / 5` = **3**（整数除法，小数被砍掉）；`17 % 5` = **2**（17 = 5×3 + 2）；
`17 / 5.0` = **3.4**（有一个是小数，按小数运算）。
**注意**：`17 / 5.0` 结果是 `3.4`，不是 `3.40` —— 打印时写 `%.2f` 才会显示两位。

**A2.** `n % 7 == 0`
**核心认知**：**"a 能被 b 整除" ⇔ `a % b == 0`**。这个等价关系以后天天用。

**A3.** 因为 `%` 和 `/` **优先级相同、左结合**，`num / 10 % 10` 等价于 `(num / 10) % 10`：
- `num / 10` = 48 → 先把个位砍掉；
- `48 % 10` = 8 → 再取出现在的最后一位，也就是原来的十位。

而 `num % 10 / 10` 是 `(num % 10) / 10`：
- `num % 10` = 3 → 先取出个位；
- `3 / 10` = **0** → 整数除法，答案是 0，完全错了。

**口诀**：**先 `/` 砍掉尾巴，再 `%` 取出新尾巴。**

**A4.** 输出 **`5`**。
因为 `x = 5` 是**赋值**，不是判断：它把 5 放进 x，而**整个赋值表达式的值就是 5**，所以打印 5。
**危险在于**：① 你以为在判断"x 是不是 5"，其实没判断；② **x 被悄悄改掉了**，
后面所有用到 x 的代码都会跟着错。
**正确写法**：`printf("%d\n", x == 5);` → 输出 `1`。

**A5.** `n` 还是 **0**。
因为 `0 && ...` 的左边是假，`&&` 的结果**一定是假**，所以右边 `(n = 99)` **根本没执行**。
这就是**短路求值**。
（如果写成 `1 && (n = 99)`，`n` 就会变成 99。）

**A6.** 分别是 **1.5** 和 **1.0**。
- `(double)3 / 2`：`(double)` 只作用在紧挨着的 `3` 上 → `3.0 / 2` = 1.5 ✅
- `(double)(3 / 2)`：先算括号里的 `3 / 2`（两个整数！）= 1，再转成 1.0 ❌

**记忆**：**`(类型)` 只戴在紧挨着的那一个操作数上**；想得到小数，必须在**做除法之前**就变成小数。

**A7.** **不会报错，一句警告都没有**（因为 `big` 是变量，编译器编译期不知道它的值）。
结果：**`bigger` 是 `-2147483648`** —— 正数变成了负数，程序还"正常结束"（退出码 0）。
**原因**：`int` 最大只能到 `2147483647`，再加 1 就溢出了。
**性质**：有符号整数溢出是**未定义行为（UB）**，C 标准不保证任何结果。
**验证工具**：编译时加 `-fsanitize=undefined`，UBSan 会当场报错。

</details>
