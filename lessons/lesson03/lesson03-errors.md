# 第 3 课 · 常见报错速查（真实原文对照）

> 所有报错信息都是**在你自己的电脑上实测粘贴下来的**（Apple clang 21 / macOS arm64 / Apple Silicon）。
>
> **第 3 课的性质变了**：前两课的报错以"写错了"为主，本课的报错以
> **"写对了语法、但算错了结果"** 为主 —— 后者危险 10 倍，因为编译器往往一声不吭。

---

## 一、本课关键词总览

| 关键词 | 出现在哪 | 严重程度 | 意味着 |
| --- | --- | --- | --- |
| `expression is not assignable` | 编译 error | 低（抓得住） | 你把赋值号左边写成了不能赋值的东西（如 `17 % 2 = 0`） |
| `invalid operands to binary expression` | 编译 error | 低 | 运算符用错类型（如 `10.0 % 3`） |
| `-Wunused-comparison` | 编译 warning | 中 | 你算了一个比较，但结果没用（常常是 `==` 写成了 `=`） |
| `-Wsign-compare` | 编译 warning | **高** | 有符号和无符号比较，负数会被"变成"巨大正数 |
| `-Wconstant-logical-operand` | 编译 warning | 中 | 你用常量做 `&&`/`\|\|`，clang 怀疑你想写按位运算 `&` |
| **什么都没有** ⚠️ | —— | **最高** | 整数除法、`=`/`==` 混用、整数溢出、除以零 |

> 🎯 **本课最重要的一句话**
> **"没有报错"不等于"结果正确"。** 本页最后三节（溢出、除以零、`=`/`==`）
> 全都是在你这台机器上**零警告、退出码 0、结果却完全是错的**。

## 二、⚠️ 头号杀手：把 `==` 写成 `=`（编译**不报错**）

**真实运行结果（零警告，退出码 0）：**

```text
x 等于 5 吗？ 5
x = 5
```

| 项目 | 内容 |
| --- | --- |
| **你的意图** | `x == 5` —— 判断 x 是不是 5，应该输出 `1` |
| **实际发生** | `x = 5` —— 把 5 赋给 x，整个表达式的值就是 5，所以打印出 5 |
| **更糟的后果** | 你的 x **被悄悄改掉了**，后面所有用到 x 的地方全错 |
| **编译器在干嘛** | `printf` 里用赋值表达式是合法语法，所以**一句警告都没有** |

**什么时候能有警告？** 只有当这个比较**作为一个独立语句**、结果完全被丢弃时：

```text
p5.c:2:38: warning: equality comparison result unused [-Wunused-comparison]
    2 | int main(void) { int a = 7, b = 2; a == b; return 0; }
      |                                    ~~^~~~
p5.c:2:38: note: use '=' to turn this equality comparison into an assignment
    2 | int main(void) { int a = 7, b = 2; a == b; return 0; }
      |                                      ^~
      |                                      =
1 warning generated.
```

**防身三条**：

1. **判断相等永远写两个等号**，写的时候嘴里念出来："等于等于"；
2. 比较的结果**一定要用掉**（打印出来、或者存进变量）—— 这样 `=` 和 `==` 的差别就会暴露；
3. **看到 `-Wunused-comparison`，第一反应是"我这里是不是想写 `=`？"**（clang 的 `note` 也是这个意思）。

## 三、`%` 只能用于整数（编译 error）

**真实报错：**

```text
p1.c:2:38: error: invalid operands to binary expression ('double' and 'int')
    2 | int main(void) { printf("%d\n", 10.0 % 3); return 0; }
      |                                 ~~~~ ^ ~
1 error generated.
```

| 项目 | 内容 |
| --- | --- |
| **人话** | "二元运算符 `%` 的操作数类型非法（`double` 和 `int`）" |
| **原因** | 取余在数学上只对整数定义，C 干脆禁止浮点取余 |
| **怎么改** | 想对小数取余，用 `fmod()`（住在 `<math.h>`，链接时可能要加 `-lm`）；或者先想清楚你到底要干什么 |
| **记住** | **`%` 的两个操作数必须都是整数类型** |

---

## 四、给不可赋值的东西赋值（编译 error）

**真实报错：**

```text
p2.c:2:40: error: expression is not assignable
    2 | int main(void) { printf("%d\n", 17 % 2 = 0); return 0; }
      |                                 ~~~~~~ ^
1 error generated.
```

| 项目 | 内容 |
| --- | --- |
| **人话** | "这个表达式不能被赋值" |
| **原因** | `17 % 2` 算出来是一个**值**（临时结果），不是"盒子"，没法往里放东西 |
| **典型场景** | 想判断"17 是偶数吗"，把 `==` 写成了 `=` → `17 % 2 = 0` |
| **怎么改** | `17 % 2 == 0`。**判断用 `==`，赋值用 `=`，别混** |
| **补充理解** | 赋值号左边必须是"能被放东西的东西"：变量、数组元素等（叫左值 lvalue） |

## 五、`-Wsign-compare`：有符号和无符号比较（**结果会骗你**）

**真实警告：**

```text
sign.c:6:76: warning: comparison of integers of different signs: 'int' and 'unsigned int' [-Wsign-compare]
    6 |     printf("-1 < 1u 的结果 = %d   <- 你以为 1，其实是 0！\n", i < u);
      |                                                               ~ ^ ~
1 warning generated.
```

**真实运行结果（这才是可怕的地方）：**

```text
-1 < 1u 的结果 = 0   <- 你以为 1，其实是 0！
因为 -1 被转成了无符号数：4294967295
```

| 项目 | 内容 |
| --- | --- |
| **原因** | 混合运算时，`int` 会被**隐式转换成 `unsigned int`**；`-1` 一转就变成了 `4294967295` |
| **结果** | 数学上 `-1 < 1`，程序里却是 `4294967295 < 1` → **假** |
| **怎么改** | 别把有符号和无符号混着比；明确写 `(int)u` 或统一用有符号类型 |
| **什么时候遇上** | 和 `sizeof` 比较（`sizeof` 是 `size_t`，无符号）最容易踩：<br>`if (i < sizeof(arr))` 就是经典 bug |
| **记住** | **看到 `-Wsign-compare` 不要忽略，它在说"这次比较可能不是你想要的"** |

## 六、`-Wconstant-logical-operand`：用常量做逻辑运算

**真实警告：**

```text
logic_const.c:4:15: warning: use of logical '&&' with constant operand [-Wconstant-logical-operand]
    4 |     int r = 5 && 3;
      |               ^  ~
logic_const.c:4:15: note: use '&' for a bitwise operation
    4 |     int r = 5 && 3;
      |               ^~
      |               &
logic_const.c:4:15: note: remove constant to silence this warning
    4 |     int r = 5 && 3;
      |               ^~~~
1 warning generated.
```

| 项目 | 内容 |
| --- | --- |
| **人话** | "你对一个常量用了逻辑 `&&`" |
| **clang 在怀疑什么** | 你是不是**想写按位与 `&`**？（`5 & 3` = 1，`5 && 3` = 1，结果碰巧一样，但语义完全不同） |
| **为什么 c 语言要警告** | 在 C 里 `x & y` 和 `x && y` 是两个完全不同的运算符，写错极其常见 |
| **怎么改** | 想清楚你要逻辑运算还是位运算；用变量代替常量；真要用常量就明确写 `(5 != 0) && (3 != 0)` |
| **顺手认识** | 按位运算符 `&` `\|` `^` `~` `<<` `>>` 是你**之后**会学的（本课不要求），但今天先知道 `&&` 和 `&` **不是一回事** |

> 顺带说明：`0 && x`、`1 || x` 这类**用 0/1 常量**的写法 clang **不会**警告 ——
> 因为 0 和 1 本来就是布尔值的标准写法，一看就是故意的。

## 七、⚠️ 有符号整数溢出（**零警告**，属于未定义行为）

**真实编译结果：一句警告都没有。**

**真实运行结果：**

```text
big + 1 = -2147483648
[退出码 0]
```

| 项目 | 内容 |
| --- | --- |
| **原因** | `int` 最大只能表示 `2147483647`（`INT_MAX`），再加 1 就"绕回去"变成了最小值 |
| **为什么没警告** | 因为 `big` 是变量，编译器在编译期不知道它到底是多少 |
| **为什么危险** | 结果错得离谱（正数变负数），程序却"正常结束"（退出码 0） |
| **C 标准怎么说** | **有符号整数溢出是"未定义行为"（UB）** —— 编译器爱怎么处理都行，你不该依赖任何具体结果 |
| **怎么改** | ① 换更大的类型（`long long`）；② 计算前先检查边界；③ 用 `limits.h` 里的 `INT_MAX` 判断 |

**用 UBSan（`-fsanitize=undefined`）立刻现出原形：**

```text
p4.c:2:57: runtime error: signed integer overflow: 2147483647 + 1 cannot be represented in type 'int'
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior p4.c:2:57
```

> 🔧 **UBSan 是你从本课起要认识的武器**：编译时加 `-fsanitize=undefined`，
> 它会在运行时抓住"溢出、越界、除以零"这类编译器平时不管的错误。
> 你可以把它加到 VSCode 任务里自己用。

## 八、⚠️ 除以零 / 取余零（**在 Apple Silicon 上竟然不崩溃！**）

**真实编译结果：一句警告都没有**（因为除数是变量）。

**真实运行结果（本机实测，退出码 0）：**

```text
7 / 0 = 0
7 % 0 = 7
[退出码 0]
```

| 项目 | 内容 |
| --- | --- |
| **你可能以为** | 除以零会崩溃（很多人是这么被教的） |
| **本机真相** | **Apple Silicon（arm64）的除法指令遇到除数为 0 时，直接返回 0，不报错、不崩溃** |
| **为什么** | 这是 ARM 架构的硬件行为。在 x86 的 Intel Mac / Linux 上，同样的代码通常会收到 `SIGFPE` 信号而崩溃 |
| **哪个更糟** | **不崩溃更糟！** 崩溃至少你知道出事了；这里是**悄悄给你一个错答案**（`7 / 0 = 0`、`7 % 0 = 7`） |
| **怎么改** | **在除法/取余之前，先确认除数不是 0** —— 这正是第 4 课 `if` 要解决的第一个实际问题 |

**用 UBSan 抓它：**

```text
div0.c:6:30: runtime error: division by zero
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior div0.c:6:30
div0.c:7:31: runtime error: division by zero
SUMMARY: UndefinedBehaviorSanitizer: undefined-behavior div0.c:7:31
```

> 🎓 **这一节是本课最有价值的一课**：
> 同一段"未定义行为"的代码，在 Intel 上崩溃、在 Apple Silicon 上静默算错。
> **所以"在我电脑上是对的"从来不是理由。**

## 九、速查小结（建议打印）

| 你看到的 / 遇到的 | 原因 | 一句话修法 |
| --- | --- | --- |
| `expression is not assignable` | 赋值号左边不是一个"盒子"（如 `17 % 2 = 0`） | 判断要用 `==` |
| `invalid operands to binary expression` | `%` 用在了浮点上 | `%` 只能用于整数 |
| `-Wunused-comparison` | 比较的结果没被使用 | 你是不是想写 `=`？还是忘了用结果？ |
| `-Wsign-compare` | 有符号 vs 无符号 | 别混着比，负数会被当成巨大正数 |
| `-Wconstant-logical-operand` | 常量做 `&&` / `\|\|` | 想清楚要逻辑还是按位；用变量代替常量 |
| **结果不对但零警告** | 整数除法 / `=` 混 `==` / 溢出 / 除以零 | 逐个对照本页第二、七、八节 |

## 十、从本课起的自检三问

每次写完用到运算符的代码，问自己三句话：

1. **这里有没有整数除法？**（我是不是想要小数？）
2. **我写的 `=` 到底是"赋值"还是想"比较"?**
3. **这里有溢出的可能吗？除数会不会是 0？**

> 这三问，能拦住新手 90% 的"零警告错误"。
