# 第 3 课 · 我的疑问（lesson03-questions.md）

> **这个文件是干嘛的**
> 学这一课的过程中，凡是**没听懂、想不通、觉得奇怪**的地方，随手写在这里。
> 不用写得漂亮，写"人话"就行 —— 你写得越具体，我回答得越准。
>
> **什么时候提交**
> 做完作业后对我说一句「**批改第 3 课**」，我会在批改报告之后**逐条回答**这里的疑问。
> 没有疑问也没关系：写一句"本课无疑问"即可。

## 写疑问的推荐格式

```markdown
## 疑问 N
- **在哪里**：（例如：lesson03-lecture.md 第 5 节 / task3 第 20 行 / 自己写的时候）
- **我不懂的是**：（用你自己的话说，说错也没关系）
- **我自己猜过**（可选）：（写了我能知道你的思路卡在哪一步）
```

## 本课特别欢迎这几类疑问（第 3 课的"高危区"）

## 疑问示例（**这是示例，不是真疑问，别照着抄**）

> ## 疑问 1
> - **在哪里**：lesson03-lecture.md 第 5.1 节，短路求值
> - **我不懂的是**：讲义说 `0 && (n = 99)` 里右边不会执行。
>   可是编译器既然要"算出整个表达式的值"，它凭什么可以先不看右边就下结论？
> - **我自己猜过**：我猜是因为 `&&` 的规则是"只要有一边假，结果就是假"，
>   所以左边是假时，右边是什么都不影响最终答案。
>   但我不确定编译器是不是**保证**这样做，还是只是"碰巧优化成这样"。
> - **想学到什么程度**：想确认这是"语言保证的行为"还是"编译器的心情"。

**为什么这个示例写得好**：它问了**"是保证还是巧合"** ——
这是学 C 语言最重要的一个问题（因为 C 里"未定义行为"到处都是）。
能提出这种问题，说明你已经开始用工程师的眼光看语言了。

### 小提示

不只有"看不懂"才算疑问，下面这些同样价值很高：

- **想验证理解**："`7 / 2.0` 里，是 7 先变成 7.0，还是先把结果算成 3.5 再转？"
- **怀疑写法**："我写 `(double)a / b`，同事会不会觉得多余？有必要吗？"
- **想提前知道**："第 4 课的 `if (x = 5)`，编译器到底会怎么抓我？"
- **觉得奇怪**："为什么 `%` 这个符号既当'取余'又当'printf 的占位符'，不冲突吗？"
