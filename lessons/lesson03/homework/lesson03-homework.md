## 必做 1 ⭐⭐ 拆位与整除（`/` 和 `%` 的综合练习）

**文件**：[task1_digits.c](task1_digits.c)

**任务**：读入一个**三位正整数**（100 ~ 999），把它拆开并做整除判断。

**输出规格**

1. 第一行是提示语：`请输入一个三位正整数：`（用 `scanf` 读入一个整数）；
2. 提示语后**空一行**，然后输出 8 行；
3. 每行格式：**标签宽 16、左对齐**，中间 ` = `，**数值宽 3、右对齐**；
4. 8 行的标签和顺序**必须完全一致**（见下方形状）；
5. 后面 4 行的值是**比较运算的结果**（0 或 1），不是 0/1 手写死的。

**期望形状（输入 `483` 时，这就是程序的真实输出，共 22 字符宽）**

```text
number           = 483
hundreds digit   =   4
tens digit       =   8
ones digit       =   3
sum of digits    =  15
divisible by 2   =   0
divisible by 3   =   1
ones is even     =   0
```

**含义对照**（免得你猜标签）：

| 标签 | 要输出什么 |
| --- | --- |
| `number` | 你输入的那个数本身 |
| `hundreds digit` | 百位数字 |
| `tens digit` | 十位数字 |
| `ones digit` | 个位数字 |
| `sum of digits` | 三位数字之和 |
| `divisible by 2` | 能被 2 整除吗（`n % 2 == 0` 的结果） |
| `divisible by 3` | 能被 3 整除吗 |
| `ones is even` | **个位数字**是偶数吗 |

**我会检查什么**

- 我实测时会喂 **`483`、`100`、`999`** 三组输入（写死答案会立刻露馅）；
- 8 行是否都是 22 字符、标签列与数值列是否严格对齐（逐字符测量）；
- 拆位是否用了 `/` 和 `%`（而不是别的花招）；
- 0 错误 0 警告。

## 必做 2 ⭐⭐⭐ 改错题（2 error + 1 warning + **3 个零警告错误**）

**文件**：[task2_fixme.c](task2_fixme.c)

下面这段代码有 **6 个问题**：

- **2 个 error**（编译直接失败）
- **1 个 warning**（编译期能看到）
- **3 个编译器完全不报错、但结果是错的** ⚠️ **本课重点，全靠你自己**

```c
#include <stdio.h>

int main(void)
{
    int a = 7, b = 2;

    double average = a / b;
    printf("a 除以 b 的平均值 = %.2f\n", average);

    int n = 10;
    printf("n 是偶数吗？ %d\n", n % 2 = 0);

    printf("10 除以 3 的余数 = %d\n", 10.0 % 3);

    int x = 5;
    int y = 0;
    printf("x 等于 5 吗？ %d\n", y = x);

    a == b;

    int big = 2147483647;
    int bigger = big + 1;
    printf("big + 1 = %d\n", bigger);

    return 0;
}
```

**要求**

1. 把改正后的**完整代码**写进 `task2_fixme.c`，编译 **0 error 0 warning**；
2. 在「错误分析」区**逐条写出 6 个问题**，每条包含：
   - 大概位置（**写成"原题第 N 行（我的文件第 M 行）"** —— 上次这里被扣过分）
   - 类型：`error` / `warning` / **零警告逻辑错误**
   - 用你自己的话说清"为什么错、错在哪"
3. **明确标出 3 个"编译器不报错但结果是错的"分别是哪几条**；
4. 运行验证，程序的输出必须是：

```text
a 除以 b 的平均值 = 3.50
n 是偶数吗？ 1
10 除以 3 的余数 = 1
x 等于 5 吗？ 1
big + 1 = 2147483648
```

> ⚠️ 注意最后一行：`2147483647 + 1` 的正确结果是 **`2147483648`**，
> 而 `int` 装不下它。**所以你要换一个能装下它的类型** —— 想想第 2 课你认识的那些类型。

**我会检查什么**

- 6 处是否全部正确处理；
- 错误分析能否分清 **error / warning / 零警告错误** 三类；

## 选做 4 ⭐⭐⭐⭐ 秒数拆解（`/` 和 `%` 的经典应用）

**文件**：[challenge_seconds.c](challenge_seconds.c)

**任务**：读入一个**总秒数**，把它拆成"天 / 小时 / 分 / 秒"。

**换算关系**

```text
1 天  = 86400 秒
1 小时 =  3600 秒
1 分   =    60 秒
```

**要求**

1. 提示语 + `scanf` 读入一个整数（总秒数）；
2. 输出格式**必须完全一致**（下面是我的真实实测结果）：

```text
请输入总秒数：98765
98765 秒 = 1 天 3 小时 26 分 5 秒
```

3. 我会喂三组数据验证：

| 输入 | 应该输出 |
| --- | --- |
| `98765` | `98765 秒 = 1 天 3 小时 26 分 5 秒` |
| `3661` | `3661 秒 = 0 天 1 小时 1 分 1 秒` |
| `59` | `59 秒 = 0 天 0 小时 0 分 59 秒` |

4. **思考题**（用文字回答在注释里，不用写代码）：
   > 反过来，如果给你"天、小时、分、秒"四个数，让你算出**总秒数**，
   > 表达式怎么写？（提示：这次用的是 `*` 和 `+`，不需要 `%`）

**提示（不是答案，是思路方向）**

- 先想："天"是用 `/ 86400` 还是 `% 86400` 取出来的？
- 取完天数之后，**剩下的秒数**怎么表示？（这就是为什么要用 `%`）
- 小时同理 —— 先在草稿纸上把 98765 一步步算一遍，再写代码。

**为什么做这题**：这是"拆位"思路在**真实单位换算**上的第一次应用。
它的思维模式和作业 1 拆十进制位是**完全一样**的，只是"进制"从 10 变成了 60 和 24。
