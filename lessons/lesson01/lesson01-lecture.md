## 1. 程序到底是什么？—— 源码、编译器、可执行文件

先建立最朴素的认识：

| 角色 | 类比 | 实际是什么 |
| --- | --- | --- |
| 你写的 `.c` 文件 | 菜谱 | **人**能看懂的文本（叫**源代码**） |
| 编译器 `clang` / `cc` | 厨师 | 把菜谱翻译成**机器**能执行的命令 |
| 编译出来的文件 | 端上桌的菜 | **可执行文件**（二进制，人看不懂） |

**关键认知**：你写的 `.c` 文件**电脑不能直接运行**。
必须经过编译器翻译，生成一个可执行文件，才能真正跑起来。
这也是为什么"我代码写好了"和"我看到结果了"之间，永远夹着一个编译动作。

### 编译其实分了 4 步（知道有这么回事就行）

我用本课的 `01_hello.c` 在你这台机器上**真实跑了一遍**，结果如下：

| 步骤 | 命令 | 产物 | 实测结果 |
| --- | --- | --- | --- |
| ① 预处理 | `cc -E 01_hello.c -o 01_hello.i` | `.i` 文本 | 578 行（`#include` 把整个工具箱都展开了） |
| ② 编译 | `cc -S 01_hello.c -o 01_hello.s` | `.s` 汇编 | 只有 36 行 |
| ③ 汇编 | `cc -c 01_hello.c -o 01_hello.o` | `.o` 目标文件 | `Mach-O 64-bit object arm64` |
| ④ 链接 | `cc 01_hello.o -o 01_hello` | 可执行文件 | `Mach-O 64-bit executable arm64` |

平时我们不下这 4 条命令，而是**一条搞定**（它自动帮你做完 4 步）：

```bash
cc -std=c17 -Wall -Wextra -Wpedantic -g 01_hello.c -o 01_hello
```

这条命令的每个部分都要认识（以后天天用）：

| 片段 | 含义 |
| --- | --- |
| `cc` | 调用编译器（本机 `cc` 就是 Apple clang 21） |
| `-std=c17` | 按 **C17 标准**检查我的代码 |
| `-Wall -Wextra -Wpedantic` | **警告全开**——把编译器当成严格的老师 |
| `-g` | 生成调试信息，`F5` 打断点调试需要它 |
| `01_hello.c` | 输入：源代码 |
| `-o 01_hello` | 输出：可执行文件叫 `01_hello` |

> 💡 **为什么一定要开警告？**
> C 语言非常"宽容"，很多明显的错误编译器只给**警告**不给错误，程序照样能跑，
> 但结果是错的。开着 `-Wall -Wextra`，等于让编译器帮你把隐患喊出来。
> 本课作业的标准就是：**0 错误、0 警告**。

## 2. 逐行拆解：你的第一个 C 程序

打开 [examples/01_hello.c](examples/01_hello.c)（在 VSCode 里点开，边看边对照）：

```c
#include <stdio.h>      /* 把 stdio.h 这个"工具箱"搬进来：printf 就住在里面 */

int main(void)          /* main 是程序的入口，操作系统从这里开始执行 */
{                       /* 左花括号：函数体开始 */

    printf("你好，C 语言！\n");   /* 打印一句话；\n 的作用是"换行" */
    printf("Hello, C!\n");       /* 再来一句，这次是英文 */

    return 0;           /* 把 0 交还给操作系统，表示"正常结束" */

}                       /* 右花括号：函数体结束 */
```

一行一行来：

### ① `#include <stdio.h>` —— 借用别人的工具箱

- `stdio` = **st**andard **i**nput **o**utput（标准输入输出）。
- 把 `printf`（负责"往屏幕上写字"）这个功能搬进你的程序。
- **没有这一行，就用不了 `printf`**，编译器会报 `call to undeclared function 'printf'`。
- 这一行**不需要分号**，注意结尾是 `>` 不是 `>;`。

### ② `int main(void)` —— 程序的唯一入口

- 程序里面有几十个函数，但操作系统**只认 `main`**，一定从这里开始执行。
- `int` 表示：这个函数结束时，要交给系统**一个整数**。
- `(void)` 表示：这个函数**不接收任何参数**。
- ⚠️ 名字必须是小写 `main`。写成 `Main` 程序就找不到入口，链接时会失败。

### ③ `{` 和 `}` —— 圈定"这里是我的地盘"

- 一对花括号包住的，就是这个函数的**函数体**（要做的事都写在里面）。
- 花括号**不写分号**，它成对出现，写的时候**养成同时敲一对再回头填内容**的习惯。
- 缩进是给**人**看的，编译器不在乎；但缩进乱了，你自己会先崩溃 —— 我们统一 **4 个空格**。

### ④ `printf("...");` —— 你和程序之间的嘴

```c
printf("你好，C 语言！\n");
 └──┬─┘└──────┬────────┘ └┬┘
  函数名    要打印的内容   分号
```

- 双引号里的叫**字符串**，就是"要原样吐出来的一段文字"。
- `\n` 不是两个字符 `\` 和 `n`，它是**一个换行符**（下一节细讲）。
- 行尾的 `;` 是**语句结束的标志**，中文叫分号，英文叫 semicolon。**C 语言的每一句"动作"后面都必须有它。**

### ⑤ `return 0;` —— 向系统报告"我干完了，一切正常"

- `0` 是约定俗成的"成功"代码（非 0 表示出问题了）。
- 在终端里用 `echo $?` 可以看到这个返回值；正常退出就是 `0`。

### 本程序实测输出

```text
你好，C 语言！
Hello, C!
```

编译结果：**0 错误 0 警告**。程序退出码：`0`。

> 🎯 **必须背下来的两个标点和一个陷阱**
> 1. 每一句语句结尾要 `;`（英文分号，**不是** `；`）
> 2. `#include` 那一行**不要**加分号
> 3. C 语言**区分大小写**：`printf` ≠ `Printf`；`main` ≠ `Main`

## 3. 注释：写给"三天后的自己"的话

注释是**给人和未来的你看的**，编译器扫到就跳过，不产生任何影响。

```c
// 单行注释：从 // 开始，到这一行结束

/*
 * 多行注释：从 斜杠+星号 开始，到 星号+斜杠 结束（我这里加空格是为了不被提前结束）
 * 可以写很多行
 * 注意：多行注释不能嵌套！别在里面再写一对
 */
```

**为什么初学就要用注释？** 因为你三天后回看自己的代码，80% 会想"这行在干嘛"。

## 4. 转义字符：看不见的字符怎么表示

屏幕上看不见"换行"这个动作，所以 C 用一个特殊写法表示它：**反斜杠 `\` + 一个字母**。

打开 [examples/02_escapes.c](examples/02_escapes.c) 跑一遍，下面是**你的机器上的真实输出**：

```text
1. 最普通的一行
2. 反斜杠 n 让光标跳到下一行

3. 反斜杠 t 是制表符：姓名	年龄	城市
4. 想在屏幕上打出双引号，要写 \" ：
   他说："你好，世界"
5. 想在屏幕上打出反斜杠，要写两个：C:\Users\student\code
6. 想在屏幕上打出百分号，要写两个：正确率 100%
```

对照表（**这张表要记住，以后天天用**）：

| 你写在代码里 | 屏幕上实际出现的 | 说明 |
| --- | --- | --- |
| `\n` | 换行（光标跳到下一行） | 最常用，没有之一 |
| `\t` | 一个制表位（约 8 个空格宽） | 做列对齐 |
| `\"` | `"` | 想在字符串里打出双引号 |
| `\\` | `\` | 想打出反斜杠本身 |
| `%%` | `%` | ⚠️ **特殊**：它不是 `\` 开头，是写两个百分号 |

**两个最容易困惑的点，现在就说透：**

1. **为什么 `\n` 打印出来不是 `\n`？**
   因为编译器看到 `\` 就知道"后面这个不是普通字符"，于是把它翻译成一个**换行动作**。
   你想真的打印出 `\n` 这两个符号，得写 `\\n`。
2. **为什么百分号要写两个？**
   因为 `%` 在 `printf` 里是"占位符"的开头（第 2 课学输入输出格式时会讲透）。
   想打印一个真正的 `%`，就必须写 `%%`。

## 5. `printf` 排版：你敲几个空格，屏幕上就有几个空格

这是本课最重要的"输出认知"。

打开 [examples/03_printf_practice.c](examples/03_printf_practice.c)，**实测输出**：

```text
+--------------------------------+
|         MY C JOURNEY           |
+--------------------------------+
| Name    : Alex                 |
| Lesson  : 01 - Hello, C        |
| Editor  : VS Code              |
| Compiler: Apple clang (C17)    |
+--------------------------------+
| Progress: [####------]  40%    |
+--------------------------------+

目标：打牢编程基础，把每一行代码都"真正看懂"。
```

**规律**：`printf` 就是"原样吐出来"，唯一例外是 `\` 开头的转义字符。所以：

- 边框是**手写**的：`+` 加 32 个 `-` 加 `+`。
- 对齐是**手数空格**的：`| Name    : ` 里 `Name` 后面补 4 个空格，是为了让 `:` 和第 2 行的 `Lesson` 对齐。
- 这一行解释了为什么用 `%%`：

```c
printf("| Progress: [####------]  40%%    |\n");
                                      └┬┘
                              写一个，屏幕上出一个 %
```

> 🧠 **小知识（中国学生会踩的坑）**
> 一个中文字符在终端里占 **2 个字符宽度**，英文占 1 个。
> 所以中文和英文混排做边框时，靠"数空格"很难对齐。
> 例子最后那行中文我故意放在框外 —— 工程上常见做法是：**要么全中文，要么全英文**。

## 7. 小测验（先自己想，再展开答案）

**Q1.** 判断对错：C 语言里 `Printf("hi\n");` 和 `printf("hi\n");` 效果一样。

**Q2.** 下面哪一句能让屏幕上**出现两行**内容？
A. `printf("A\nB");` B. `printf("A\tB");` C. `printf("A\\nB");`

**Q3.** 我想让程序输出 `完成度 100%`，应该怎么写？

**Q4.** 编译报错 `error: expected ';' after expression`，最可能的原因是什么？

**Q5.** `main` 最后的 `return 0;` 是干什么用的？不写会怎样？

<details>
<summary>👉 点这里展开答案与解析</summary>

**A1.** **错。** C 语言严格区分大小写，`Printf` 是"未声明的函数"，
编译器会报 `call to undeclared function 'Printf'` 并提示 `did you mean 'printf'?`。

**A2.** **A。** `\n` 是换行，所以 A 输出两行（`A` 和 `B`）。
B 的 `\t` 只是横向跳到制表位，仍在同一行；
C 的 `\\n` 会**打印出字面的 `\n` 两个符号**，也是一行。

**A3.**

```c
printf("完成度 100%%\n");
```

关键是 `%%`：两个百分号在屏幕上变成**一个** `%`。

**A4.** **上一句（或本句）末尾漏了英文分号 `;`。**
这个报错的位置往往指向**报错行的末尾**，但真正的问题常常在**上一行**。
辅助判断：如果你不小心用了中文分号 `；`，编译器还会额外警告
`treating Unicode character <U+FF1B> as an identifier character`。

**A5.** `return 0;` 是把"退出码 0"交给操作系统，表示程序**正常结束**。
- 写了：规范和调试都方便，`echo $?` 能看到 0；
- 在 C99/C11/C17 标准下，`main` 不写 `return` 也能编译通过，编译器会默认返回 0。
- **但本课要求你写**：这是养成"明确表达意图"的好习惯，而且这是绝大多数真实项目的写法。

</details>
