# 第 4 课 · 我的疑问（lesson04-questions.md）

> **这个文件是干嘛的**
> 学这一课的过程中，凡是**没听懂、想不通、觉得奇怪**的地方，随手写在这里。
> 不用写得漂亮，写"人话"就行 —— 你写得越具体，我回答得越准。
>
> **什么时候提交**
> 做完作业后对我说一句「**批改第 4 课**」，我会在批改报告之后**逐条回答**这里的疑问。
> 没有疑问也没关系：写一句"本课无疑问"即可。

## 写疑问的推荐格式

```markdown
## 疑问 N
- **在哪里**：（例如：lesson04-lecture.md 第 5 节 / task3 第 20 行 / 自己写的时候）
- **我不懂的是**：（用你自己的话说，说错也没关系）
- **我自己猜过**（可选）：（写了我能知道你的思路卡在哪一步）
- **想学到什么程度**：（只要会用 / 想彻底搞懂原理）
```

## 本课特别欢迎这几类疑问（第 4 课的"高危区"）

| 类型 | 可能的疑问 |
| --- | --- |
| **双括号的疑惑** | "既然 `if ((x = 5))` 能消警告，那我加双括号不就行了？什么时候真该这么做？" |
| **switch 的设计** | "为什么 `switch` 不能写 `case >= 60`？设计上为什么不支持范围？" |
| **fallthrough** | "既然忘记 `break` 这么危险，为什么 C 不干脆让 `case` 自动 `break`？" |
| **悬挂 else** | "C 为什么规定 `else` 匹配最近的 `if`？这不是故意制造陷阱吗？" |
| **三目的取舍** | "三目和 `if-else` 到底什么时候用哪个？代码规范上有什么共识？" |
| **浮点比较** | "容差 0.000001 是怎么定的？为什么不用更小的数？" |
| **else if 顺序** | "如果我的判断条件本来就不重叠，顺序还有关系吗？" |
| **性能问题** | "`if-else` 链长了会不会变慢？`switch` 是不是比 `if` 快？" |
| **花括号** | "花括号真的有必要每层都加吗？我见过的老代码很多都不加。" |
| **布尔类型** | "`if` 里能不能直接放一个 `bool` 变量？和放 `int` 有什么区别？" |

## 疑问示例（**这是示例，不是真疑问，别照着抄**）

> ## 疑问 1
> - **在哪里**：lesson04-lecture.md 第 6 节，`if (x = 5)` 的警告
> - **我不懂的是**：第 3 课说 `printf("%d", x = 5)` 没警告，这一课说 `if (x = 5)` 有警告。
>   同样是赋值表达式，为什么编译器区别对待？它到底在哪儿划的线？
> - **我自己猜过**：我猜是因为 `if` 的括号里"应该放真假值"，编译器知道这里不该出现赋值，
>   所以专门检查；而 `printf` 的参数什么都能放，它管不着。
> - **想学到什么程度**：想确认这个猜测对不对，以及"还有哪些位置是编译器会专门检查的"。

**为什么这个示例写得好**：它把**两节课的现象联系起来**，并且尝试自己归纳规则。
这种"找规律"的提问，比问"这句话什么意思"高一个层次。

### 小提示

不只有"看不懂"才算疑问，下面这些同样价值很高：

- **想验证理解**："`else if` 链里，最后一个 `else` 不写会怎样？"
- **怀疑写法**："我把 `switch` 写成 `if-else` 链会不会更好维护？"
- **想提前知道**："第 5 课的循环里，`break` 和 `switch` 的 `break` 是同一个东西吗？"
- **觉得奇怪**："为什么 `default` 要写在最后？写在中间行不行？"
