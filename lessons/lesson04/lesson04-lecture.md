## 1. `if` 的基本形态

打开 [examples/01_if_basic.c](examples/01_if_basic.c) 跑一遍，**本机真实输出**：

```text
及格了
score = 85
及格了，可以进入下一课
程序继续往下走（if 拦不住它）
17 是奇数（这里用的是 n % 2 本身当条件）

--- 除法守卫 ---
除数 b 是 0，已拦下这次除法
```

### 1.1 三种写法

```c
/* 形态 1：只有一条语句（能省花括号，但不推荐） */
if (score >= 60)
    printf("及格了\n");

/* 形态 2：加花括号（推荐！哪怕只有一条语句） */
if (score >= 60) {
    printf("score = %d\n", score);
    printf("及格了，可以进入下一课\n");
}

/* 形态 3：条件不成立时什么都不做 —— 程序继续往下走 */
if (score >= 90) {
    printf("这一行不会执行\n");
}
printf("程序继续往下走（if 拦不住它）\n");
```

### 1.2 条件就是"0 或 1"（第 3 课的直接应用）

```c
int n = 17;
if (n % 2) {          /* 等价于 n % 2 != 0 —— 余数是 1，就是真 */
    printf("%d 是奇数\n", n);
}
```

**两种写法都对**，但我建议你写清楚：

```c
if (n % 2 != 0) { ... }    /* ✅ 更推荐：意图明确，一眼看懂 */
if (n % 2)      { ... }    /* 也可以，但读者要停一下才能反应过来 */
```

> **原则：清楚 > 聪明。** 你省下的那几个字符，会让三个月后的你多花十分钟。

### 1.3 ⭐ 实战：除法守卫（第 3 课陷阱的正式解法）

第 3 课我们实测过一个诡异现象：**在你这台 Apple Silicon 上，`7 / 0` 不崩溃，而是静默返回 0**。
当时我说"正确做法是除法之前先确认除数不为 0" —— 现在你终于有工具了：

```c
int a = 7;
int b = 0;

if (b != 0) {
    printf("a / b = %d\n", a / b);        /* 只在安全时才除 */
}
if (b == 0) {
    printf("除数 b 是 0，已拦下这次除法\n");
}
```

**这是 `if` 的第一个真实价值**：不是"让程序显得聪明"，而是**防止程序做危险的事**。

### 1.4 ⚠️ 花括号纪律：省略花括号的经典翻车

```c
if (score >= 60)
    printf("及格\n");
    printf("这句其实【不在】 if 里面！\n");   /* ⚠️ 缩进骗了你，它永远执行 */
```

**`if` 只管它后面的那一条语句。** 你以为缩进是"归属"，但 C 语言不看缩进，只看语法。

> **纪律：只要你写 `if`，就顺手写一对花括号。**
> 省下来的两个字符，不值得用一个 bug 去换。

## 2. `if - else`：二选一

打开 [examples/02_if_else.c](examples/02_if_else.c)：

```text
-7 是负数
|-7| = 7
42 是偶数
（isEven 里存的就是 1）
```

```c
if (n >= 0) {
    printf("%d 是非负数\n", n);
} else {
    printf("%d 是负数\n", n);
}
```

**关键性质**：`if` 和 `else` **一定恰好执行一个** —— 不可能都执行，也不可能都不执行。
（这和第 1 节提到的"两个独立的 `if`"完全不同。）

**经典应用：求绝对值**

```c
int absValue = 0;
if (n >= 0) {
    absValue = n;
} else {
    absValue = -n;
}
```

**花括号纪律的第二种表现**：一边有花括号、一边没有，是极易改错的结构。

```c
if (n > 0) {
    printf("正数\n");
} else
    printf("非正数\n");     /* ❌ 一边有一边没有，将来加一行就出事 */
```

## 3. `else if` 链：多分支（**顺序至关重要**）

打开 [examples/03_else_if_chain.c](examples/03_else_if_chain.c)：

```text
score = 85

正确顺序的结果：等级 B

--- 把顺序倒过来（错误示范）---
错误顺序的结果：等级 D   <- 85 分也先掉进这里！

--- 写成几个独立的 if（不是 else if）---
如果分开写：及格
如果分开写：良好

--- 闰年判断，这次输出文字 ---
1900 不是闰年
```

### 3.1 两条铁律

**铁律 1：`else if` 链从上往下依次判断，一旦命中就整条链结束。**

```c
if (score >= 90) {              /* 先问：90 以上吗？ */
    printf("等级 A\n");
} else if (score >= 80) {       /* 再问：80 以上吗？ */
    printf("等级 B\n");          /* 85 命中这里，后面的都不看了 */
} else if (score >= 70) {
    printf("等级 C\n");
} else {
    printf("等级 F\n");
}
```

**铁律 2：范围判断必须从苛刻到宽松（通常是从高到低）。**

把顺序倒过来，85 分**第一次判断就掉进 `>= 60`**，后面的 `>= 80`、`>= 90` 永远轮不到：

```c
if (score >= 60) {              /* ❌ 85 在这里就命中了 */
    printf("等级 D\n");          /*    输出永远是 D */
} else if (score >= 80) {       /*    永远轮不到 */
```

**记忆法：`else if` 链像一道道越来越宽的筛子 —— 一定要从最细的筛起。**

### 3.2 `else if` 链 vs 多个独立 `if`

```c
/* 只选一个：用 else if 链 */
if (score >= 90)      { printf("优秀\n"); }
else if (score >= 80) { printf("良好\n"); }

/* 分别判断：用独立的 if（可能命中多个） */
if (score >= 60) { printf("及格\n"); }     /* 会执行 */
if (score >= 80) { printf("良好\n"); }     /* 也会执行 */
```

**判断标准**：问自己"这几件事是**互斥**的吗？"
- 互斥（成绩等级只能有一个）→ `else if`
- 不互斥（"及格"和"良好"可以同时成立）→ 独立 `if`

### 3.3 实战：闰年终于能说人话了

第 3 课你已经写出了闰年表达式（输出 `1`/`0`），现在能让它输出文字：

```c
int year = 1900;
if ((year % 4 == 0 && year % 100 != 0) || year % 400 == 0) {
    printf("%d 是闰年\n", year);
} else {
    printf("%d 不是闰年\n", year);
}
```

## 4. 三目运算符 `? :`：`if-else` 的表达式版

打开 [examples/04_ternary.c](examples/04_ternary.c)：

```text
score = 85
是否及格：是
是否优秀：否

a = 7, b = 2
较大的那个（max）= 7
较小的那个（min）= 2

n = -5
符号判断（嵌套三目）：负数
（上式括号里的三目是必须的 —— 三目是【右结合】的）

flag = 1 -> 真
flag = 0 -> 假
```

### 4.1 语法

```text
条件 ? 条件为真时的值 : 条件为假时的值
```

**和 `if-else` 的本质区别**：
- `if-else` 是**语句**（不能当值用）；
- 三目是**表达式**（有值），所以**能塞进 `printf`、能直接赋值**。

```c
/* 直接当值用 */
printf("是否及格：%s\n", score >= 60 ? "是" : "否");

/* 赋值场景（三目最擅长的用法） */
int max = a > b ? a : b;      /* 一行搞定"取较大者" */
```

### 4.2 和 `if-else` 的对比

```c
/* if-else 版：4 行 */
int max2 = 0;
if (a > b) { max2 = a; } else { max2 = b; }

/* 三目版：1 行 */
int max = a > b ? a : b;
```

**两者完全等价。** 简单的二选一，三目更清爽。

### 4.3 什么时候**不要**用三目

```c
/* ❌ 分支里要做多件事，就别用三目 */
score >= 60 ? (printf("及格\n"), count++) : printf("不及格\n");

/* ✅ 这种情况老老实实写 if-else */
if (score >= 60) {
    printf("及格\n");
    count++;
} else {
    printf("不及格\n");
}
```

**判断标准**：
- 只是"二选一给一个值" → 用三目；
- 分支里要做两件以上的事 → 用 `if-else`；
- 嵌套超过一层 → 用 `if-else`（嵌套三目只有写的人看得懂）。

## 5. `switch / case`：一个值 vs 一串确定的值

打开 [examples/05_switch.c](examples/05_switch.c)：

```text
day = 3
星期三

--- 忘记 break 会怎样 ---
星期三
星期四  <- 也被执行了
原因：case 命中后，程序会一直往下执行，直到遇到 break 或 switch 结束。
⚠️ 而且编译器默认【不会警告】这件事（要显式打开 -Wimplicit-fallthrough）。

--- 正当用法：多个 case 共享代码 ---
4 月有 30 天

--- switch 也能判断字符 ---
良好
```

### 5.1 基本用法

```c
switch (day) {
    case 1:
        printf("星期一\n");
        break;                  /* ⚠️ 每个 case 后面都要 break */
    case 2:
        printf("星期二\n");
        break;
    default:                    /* 兜底：以上都不匹配时 */
        printf("不在 1~4 范围内\n");
        break;
}
```

### 5.2 ⚠️ 忘记 `break`：贯穿（fallthrough）

**这是本课第二个"零警告陷阱"**（第一个是第 7 节的 `if (x = 5)` 双括号）。

`case` 命中后，程序**一直往下执行**，直到遇到 `break` 或 `switch` 结束：

```c
switch (day) {          /* day = 3 */
    case 3:
        printf("星期三\n");     /* 命中，没有 break！ */
    case 4:
        printf("星期四\n");     /* 于是这句也被执行了 */
        break;
}
```

**实测输出就是两行**：`星期三` + `星期四`。
**而且编译器默认一句话都不说** —— 想让它警告，得显式打开 `-Wimplicit-fallthrough`。

### 5.3 什么时候"故意贯穿"是正当的

多个 `case` 共享同一段代码，**空 case 连写**是标准写法：

```c
switch (month) {
    case 1: case 3: case 5: case 7: case 8: case 10: case 12:
        days = 31;              /* 这些月份都是 31 天，故意贯穿 */
        break;
    case 4: case 6: case 9: case 11:
        days = 30;
        break;
    case 2:
        days = 28;              /* 平年 2 月（闰年 29 天，作业里你来做） */
        break;
}
```

**纪律：`case` 后面要么有 `break`，要么有注释说明"我是故意的"。**

### 5.4 `switch` 的四个硬限制

| 限制 | 说明 | 后果 |
| --- | --- | --- |
| ① 只能判**相等** | 不能写 `case >= 60` | **范围判断只能用 `if-else`** |
| ② 只能对**整数** | 含 `char`、枚举；`double` 不行 | 编译 error |
| ③ `case` 必须是**编译期常量** | 不能写 `case y:`（y 是变量） | 编译 error |
| ④ case 值必须**唯一** | 重复会报错 | 编译 error |

**所以怎么选？**

```text
范围判断（>= 60、0~100 之间）  →  if-else 链
确定的值（+ - * /、1~7、'A'）  →  switch
```

## 6. ⭐ 悬念揭晓：为什么 `if (x = 5)` 会被抓住

**第 3 课留下的一个问题**：`printf("%d", x = 5)` 一句警告都没有，结果悄悄错掉。
**但同样一个 `=`，放进 `if` 的条件里，clang 立刻警告。**

**真实警告（本机实测）：**

```text
q1.c:2:35: warning: using the result of an assignment as a condition without parentheses [-Wparentheses]
    2 | int main(void) { int x = 3; if (x = 5) { printf("进来了，x=%d\n", x); } return 0; }
      |                                 ~~^~~
note: place parentheses around the assignment to silence this warning
note: use '==' to turn this assignment into an equality comparison
1 warning generated.
```

**为什么这里能抓住、`printf` 里抓不住？**

因为 **`if` 的括号是一个"条件位置"** —— C 的语法在这里特殊对待，
"条件"的用途就是判断真假，而在条件里写赋值，**几乎总是笔误**。所以 clang 在这里专门检查。
而 `printf` 的参数列表是普通表达式，怎么写都合法，编译器**没有理由**怀疑你。

**⚠️ 但双括号是个更大的陷阱：**

```c
if ((x = 5)) { ... }      /* 警告消失了！ */
```

我实测了：**加双括号后警告消失，但依然是赋值，`x` 还是变成 5**。
双括号的意思是"我知道我在赋值，别管我" —— 而通常你并不知道。

### 这三句话请记住

1. **看到 `-Wparentheses` 提到 assignment，99% 是你想写 `==`** —— 去改，别加括号消警告；
2. **别用双括号"消警告"**；
3. 真需要在条件里赋值（很少见，如 `while ((c = getchar()) != EOF)`，第 5 课后你会见到），
   那就加括号，**并在注释里说明为什么**。

### 恭喜：第 3 课那个坑，现在有保护网了

第 3 课你写 `=` 的时候是"裸奔"的；从这一课起，只要用到 `if`/`while`，
**写错的 `=` 会被编译器当场喊住**。这就是"语言特性"和"工具"互相配合的价值。

**Q1.** `if (x = 5)` 和 `if (x == 5)` 有什么区别？前者会怎样？编译器会管吗？

**Q2.** 为什么 `if (a < b < c)` 是错的？应该怎么写？

**Q3.** 找出这段代码的问题：
```c
if (score > 60);
{
    printf("及格\n");
}
```

**Q4.** `switch (x) { case 1: printf("A"); case 2: printf("B"); break; }`，当 `x = 1` 时输出什么？为什么？

**Q5.** 判断"分数在 0~100 之间"，下面的写法哪个对？
A. `if (0 <= score <= 100)`
B. `if (score >= 0 && score <= 100)`
C. `if (score >= 0 || score <= 100)`

**Q6.** 用三目运算符写一行代码，求 `a`、`b` 中的较大值。

**Q7.** 成绩等级（A/B/C/D/F）应该用 `if-else` 还是 `switch`？为什么？

<details>
<summary>👉 点这里展开答案与解析</summary>

**A1.**
- `if (x == 5)`：**判断** x 是不是 5，不会改变 x；
- `if (x = 5)`：**赋值** —— 把 5 放进 x，而且整个表达式的值就是 5（非 0）→ **条件恒为真，永远进 if**，同时 **x 被悄悄改掉了**。
- **编译器会管**：clang 警告 `-Wparentheses: using the result of an assignment as a condition without parentheses`，
  并给出两条出路（加括号 / 改成 `==`）。
- **⚠️ 补充**：写成 `if ((x = 5))` 警告就消失了，但**依然是赋值**。所以别用双括号消警告。

**A2.** 因为 C 会**从左往右算**：先算 `a < b`，得到一个 **0 或 1**，再拿这个 `0/1` 去和 `c` 比，
也就是 `(a < b) < c` —— 和数学里的"三者递增"完全不同。
**正确写法**：`a < b && b < c`。
（好消息：clang **默认就把它当错误**，你不可能不小心写错。）

**A3.** 两个问题：
1. **`if (score > 60);` 多了一个分号** —— 这个分号就是 `if` 的"语句体"（空语句），
   于是下面那个大括号块**无条件执行**，不管分数多少都会打印"及格"。
   clang 会警告 `-Wempty-body: if statement has empty body`。
2. **边界错误**：题目要求"及格"通常是 `>= 60`，而这里写的是 `> 60`（60 分会不及格）。

**正确写法**：
```c
if (score >= 60) {
    printf("及格\n");
}
```

**A4.** 输出 **`AB`**。
因为 `case 1` 执行完后**没有 `break`**，程序会继续往下执行 `case 2` 的内容 —— 这叫**贯穿（fallthrough）**。
**注意**：编译器**默认不会警告**这件事（要显式打开 `-Wimplicit-fallthrough`）。
**修法**：`case 1` 后面补 `break;`。

**A5.** **选 B。**
- A（`0 <= score <= 100`）是**数学写法**，在 C 里等价于 `(0 <= score) <= 100`，
  即 `0或1 <= 100`，**恒为真** —— 而且 clang 会直接报 error。
- B 正确：两个条件都必须成立，用 `&&` 连接。
- C 用 `||`：只要满足一个就算"在范围内"，显然不对（`-5` 会满足 `<= 100`）。

**A6.** 
```c
int max = a > b ? a : b;
```

**A7.** **必须用 `if-else`。**
因为成绩等级是**范围判断**（`>= 90`、`>= 80`…），
而 `switch` **只能判断"等于某个确定的值"**，不能写 `case >= 90`。
**判断标准**：范围 → `if-else`；确定的值 → `switch`。
