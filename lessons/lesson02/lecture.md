## 0. 先揭晓第 1 课留下的两个悬念

第 1 课最后我留了两句话没说透，现在直接给答案：

### 悬念 1：为什么 `%` 是特殊字符，非得写两个 `%%` 才能打出一个？

因为 **`%` 是 `printf` 的"暗号开关"**。`printf` 一看到 `%`，就知道
"**后面跟着的不是要原样打印的字符，而是一个占位符** —— 请把某个变量的值填到这里"。

```c
printf("我有 %d 个苹果\n", 5);
             └┬┘          └┬┘
          暗号开关      要填进去的值
```

所以想**真的**打印一个 `%`，就必须写 `%%` —— 意思是"这次不要当开关，就是个百分号"。

### 悬念 2：靠"手数空格"对齐太痛苦，有没有专业做法？

有。而且是本课的核心内容之一：**在格式符里直接写"这一格占多少字符"**，让 `printf` 自己对齐。

```c
printf("%-10s%8d\n", "Alex", 95);     /* 字符串占 10 格左对齐，整数占 8 格右对齐 */
```

第 4 节会讲透。**这就是从"手艺人"到"工程师"的那一步。**

## 1. 变量：给一块内存起个名字

### 1.1 最朴素的比喻

程序运行的时候，数据存在**内存**里。内存像一排巨大的储物柜，每个柜子有编号（地址）。
**每次都用编号太反人类了**，所以 C 让你给柜子**起名字**：

```c
int age = 18;
└┬┘ └┬┘ └┬┘
 │   │   └── 放进去的东西
 │   └────── 你给这个柜子起的名字
 └────────── 这个柜子用来装"整数"
```

### 1.2 三个动作必须分清（初学者九成混淆在这儿）

| 动作 | 英文 | 写法 | 含义 |
| --- | --- | --- | --- |
| **声明** | declaration | `int age;` | 申请一个装整数的盒子，叫 `age`（里面是**垃圾值**） |
| **赋值** | assignment | `age = 18;` | 把 18 放进这个盒子 |
| **初始化** | initialization | `int age = 18;` | 声明的同时就放好东西 |

**一条必须养成的纪律：声明时就给初值。**

```c
int age = 0;          /* ✅ 好习惯 */
int age;              /* ⚠️ 里面是垃圾值，谁也不知道是什么 */
```

为什么？报错速查第四节有真实的翻车现场（退出码 0，值却是 `-75431720`）。

### 1.3 ⚠️ 最重要的一句话：`=` 不是数学里的"等于"

```c
int score = 95;
score = score + 5;     /* 这不是方程！取出 95 → 加 5 → 再放回去 */
```

如果你用数学脑读这行，会觉得"score 怎么可能等于 score+5，无解"。
但在 C 里，**`=` 是一个动作，顺序是"先算右边，再放进左边"**：

```text
① 取出 score 里的 95
② 95 + 5 = 100
③ 把 100 放回 score
```

读作："**把右边的结果，放进左边的盒子里**"。

### 1.4 变量的命名规则

| 规则 | 例子 |
| --- | --- |
| 只能用**字母、数字、下划线** | `student_age` ✅ |
| **不能以数字开头** | `1stNumber` ❌（第 1 课见过这个报错） |
| **区分大小写** | `age` 和 `Age` 是两个不同的变量 |
| 不能用 C 的关键字 | `int` `return` `if` `for` ❌ |
| 见名知义，用英文 | `studentCount` ✅ / `a1` `bbb` ❌ |

**风格约定（我们全程统一）**：

```c
int studentCount;      /* 小驼峰：多个单词，第二个词起首字母大写 —— 推荐 */
int student_count;     /* 下划线式：Linux 世界常用，也完全可以 */
```

### 1.5 示例 1 实测输出

打开 [examples/01_variables.c](examples/01_variables.c) 跑一遍，**本机真实输出**：

```text
age   = 18
score = 95
x, y, z = 1, 2, 3
过完生日，age = 19
加 5 分之后，score = 100
x + y + z = 6
```

对照一下：`score` 从 95 变成 100，正是 `score = score + 5;` 干的事。

## 2. 为什么必须分类型：`int` / `double` / `char`

内存里的数据，本质就是一串 `0` 和 `1`。**类型决定了怎么解释这串 0 和 1**：

| 类型 | 装什么 | 字面量写法 | 第 1 课我们其实见过 |
| --- | --- | --- | --- |
| `int` | 整数 | `42`、`-7`、`0` | — |
| `double` | 小数（双精度，日常就用它） | `1.75`、`-3.14`、`0.0` | — |
| `float` | 小数（单精度，占空间小、精度低） | `62.5f`（**必须加 f**） | — |
| `char` | **单个**字符 | `'A'`、`'7'`、`'!'`（**单引号**） | 第 1 课所有字符串里的每一个字符 |

### 2.1 实测：每种类型占几个字节

用 `sizeof` 直接问编译器。运行 [examples/02_types.c](examples/02_types.c)，**本机真实输出**：

```text
students = 42
height   = 1.750000
weight   = 62.500000
grade    = A
grade 当成字符看是 A，当成整数看是 65

--- 各种类型占多少字节（本机实测）---
sizeof(char)   = 1 字节
sizeof(int)    = 4 字节
sizeof(float)  = 4 字节
sizeof(double) = 8 字节

--- 量变量和字面量 ---
sizeof(students) = 4  (变量 students)
sizeof(height)   = 8  (变量 height)
sizeof(1.75)     = 8  (小数默认是 double)
sizeof(1.75f)    = 4  (加 f 才是 float)
sizeof(42)       = 4  (整数默认是 int)
```

**三个必须知道的点**：

1. **`sizeof` 的结果要用 `%zu` 打印**（不是 `%d`）—— 它是专门的 `size_t` 类型；
2. **字面量也有类型**：`1.75` 默认是 `double`（8 字节），`1.75f` 才是 `float`（4 字节），
   `42` 默认是 `int`。这就是为什么写 `float w = 62.5f;` 要加那个 `f`；
3. **本机实测**：`int` 是 4 字节，`double` 是 8 字节 —— **不同机器/编译器可能不同**，
   所以要用 `sizeof` 去问，而不是死记。

### 2.2 有趣的一幕：`char` 的双面性

```c
char grade = 'A';
printf("%c\n", grade);      /* 输出 A     —— 当成字符看 */
printf("%d\n", grade);      /* 输出 65    —— 当成整数看 */
```

**同一个 `char`，换个格式符，就是另一个样子。** 因为字符在电脑里**本来就是用数字存的**
（这套编号叫 **ASCII 码**）。记住三个就够用了：

| 字符 | ASCII 编码 |
| --- | --- |
| `'A'` | 65 |
| `'a'` | 97 |
| `'0'`（字符零，不是数字 0） | 48 |

> 💡 **这解释了一个从第 1 课就存在的疑问**：
> 为什么 `'A'` 用单引号、`"A"` 用双引号？因为 `'A'` 是**一个数字**（65），
> 而 `"A"` 是**一段文字**（内部是一个字符数组，末尾还藏着结束符）。
> 所以 `char c = "A";` 是类型错误 —— 拿一段文字去塞进一个格子里。

### 2.3 `char` 的两个高频错误（提前打预防针）

```c
char grade = 'A';      /* ✅ 单引号 */
char grade = "A";      /* ❌ 编译报错：incompatible pointer to integer conversion */
char grade = 'AB';     /* ❌ 一个格子装不下两个字符（这叫多字符字面量，值是实现定义的） */
```

## 3. 格式符：一门"配对"的学问

`printf` 和 `scanf` 的格式符必须和变量类型**严格配对**。这张表请抄一遍：

| 类型 | `printf` 输出 | `scanf` 输入 | 备注 |
| --- | --- | --- | --- |
| `int` | `%d` | `%d` | 最常用 |
| `double` | `%f` | **`%lf`** | ⚠️ **输入输出不一样！** |
| `float` | `%f` | `%f` | |
| `char` | `%c` | `%c` | 单引号 |
| 字符串（一段文字） | `%s` | `%s` | 第 8 课细讲 |
| `sizeof` 的结果 | `%zu` | — | |

### ⚠️ 最容易踩的坑：`double` 在输入输出里格式符不同

```c
double d = 0.0;

printf("%f\n", d);        /* ✅ 输出：printf 里 %f 就能打 double */
scanf("%lf", &d);         /* ✅ 输入：scanf 里读 double 必须写 %lf */
scanf("%f", &d);          /* ❌ 错误！我实测过：编译有警告，运行时 d 根本没被写进去 */
```

我实测的后果（详见 [报错速查](errors-cheatsheet.md) 第三节）：

```text
输入小数：d=0.000000      ← 你输入了 3.14，但 d 还是 0
```

**记忆法：输出随便，输入严格。**

## 4. 宽度与精度：第 1 课悬念的正式答案

### 4.1 语法拆解

格式符其实可以带"配件"：

```text
%  -  8  .  2  f
│  │  │  │  │  └── 类型：f = 小数，d = 整数，s = 字符串，c = 字符
│  │  │  └──┴──── 精度：小数点后保留几位
│  │  └─────────── 宽度：这一格总共占多少字符
│  └────────────── 标志：- 表示左对齐（不加就默认右对齐）
└───────────────── 暗号开关
```

`%8.2f` 读作：**"给我占 8 格，保留 2 位小数，默认右对齐"**。

### 4.2 实测输出（[examples/03_format_width.c](examples/03_format_width.c)）

```text
--- 整数的宽度 ---
[   42]           ← %5d   ：5 格右对齐
[42   ]           ← %-5d  ：5 格左对齐
[00042]           ← %05d  ：5 格，左补零
[123456789]       ← %5d   ：内容比格子宽，格子自动撑大，绝不截断

--- 小数的精度 ---
pi = 3.141593     ← %f     ：不写精度默认 6 位
pi = 3.14         ← %.2f   ：2 位（会四舍五入）
pi = 3.1415926536 ← %.10f  ：10 位（double 的实际能力）
pi = [      3.14] ← %10.2f ：宽度 10 + 精度 2
pi = [3.14      ] ← %-10.2f：左对齐，格子边界看得清清楚楚
```

**看 `[` `]` 的位置**，这是理解宽度的最好方式 —— 方括号就是格子的边界。

### 4.3 实战：一张"不用数空格"的表格

```text
--- 表格：全部靠宽度控制自动对齐 ---
NAME         SCORE   HEIGHT(m)
Alex            95        1.75
Bob            100        1.82
Catherine       87        1.68
A-Very-Long-Name      60        1.70
            ↑ 名字超过 10 格 → 这一行后面的列被整体推右，表格就歪了
              结论：宽度要留足余量，宁可预留 15 格，也别刚好卡满
```

生成它的代码只有三行（内容变了也不用重排）：

```c
printf("%-10s%8s%12s\n", "NAME", "SCORE", "HEIGHT(m)");
printf("%-10s%8d%12.2f\n", "Alex", 95, 1.75);
printf("%-10s%8d%12.2f\n", "Catherine", 87, 1.68);
```

> ⚠️ **注意最后那个"翻车演示"**：`A-Very-Long-Name` 有 16 个字符，超过了 `%-10s` 给的 10 格，
> 结果这一行**后面的列被整体推右**，表格歪了。
> **教训：宽度要留余量。** 这和"手数空格"是同一个道理 —— 内容长度会变，格式要留空间。

### 4.4 三招大对比（第 1 课作业的三种对齐方式）

| 做法 | 代码 | 优点 | 缺点 | 什么时候用 |
| --- | --- | --- | --- | --- |
| **手数空格** | `printf("\| Name    : x \|")` | 最直观、最可控 | 内容一变就要重数 | 固定不变的信息卡 |
| **`\t` 制表符** | `printf("\| Name\t: x \|")` | 写起来短 | **内容一变长就崩**（第 1 课批改里实测过） | 快速打印、不在乎精确对齐 |
| **宽度控制** ⭐ | `printf("\| %-8s: %-6s\|", "Name", "x")` | **内容变长自动适应**（只要不超宽） | 要记格式符 | **正规做法，优先选它** |

**记住结论：宽度控制是专业做法。** 从这一课起，做表格/对齐类输出，默认用它。

## 5. `scanf`：程序终于会"听"了

前面所有程序都是"只会说"，从这一课起它能"听你说"了。

### 5.1 最小用法

```c
int a = 0;
printf("请输入一个整数：");     /* ① 一定要写提示语！ */
scanf("%d", &a);                /* ② 读一个整数，存到 a 里 */
printf("你输入的是 %d\n", a);   /* ③ 用起来 */
```

### 5.2 ⚠️ `scanf` 和 `printf` 最大的区别：那个 `&`

```c
printf("%d\n", a);      /* 不需要 & */
scanf("%d", &a);        /* 必须有 & ！！ */
```

**为什么？** 用最朴素的比喻：

- `printf` 是"**把 a 里的值拿出来**给人看" → 你只要告诉它 `a` 就行；
- `scanf` 是"**把数据送进 a 这个盒子**" → 你必须先告诉它**盒子在哪**，所以要给**地址** `&a`。

**`&a` 读作"a 的地址"**，你可以先把它当成一张"地址贴纸"。
（地址背后的原理叫**指针**，第 9 课专门讲，现在只要记住这条铁律。）

**忘写 `&` 的后果我实测过**：编译只有一个警告（不加 `-Werror` 就放过去了），
运行起来**直接崩溃**：

```text
Segmentation fault: 11
[退出码 139]
```

`Segmentation fault`（段错误）是 C 程序员最常看到的崩溃信息。**现在你知道了：第 2 课阶段它最常见的元凶就是 `scanf` 忘了 `&`。**

### 5.3 写 `scanf` 的三条纪律

```c
/* 纪律 1：变量先初始化（万一下面输入失败，也不会是垃圾值） */
int a = 0;

/* 纪律 2：格式符必须和类型严格配对（double 要用 %lf！） */
double d = 0.0;
scanf("%lf", &d);

/* 纪律 3：一定要写提示语，否则用户不知道该敲什么 */
printf("请输入两个整数（空格隔开）：");
scanf("%d %d", &a, &b);        /* 一个 scanf 读多个变量，每个都要 & */
```

### 5.4 示例 4 实测（我喂给它 `12` 和 `30`）

```text
请输入第一个整数（然后按回车）：请输入第二个整数（然后按回车）：
你输入的是 12 和 30
12 + 30 = 42
12 - 30 = -18
12 * 30 = 360
```

**在 VSCode 里自己跑**：用任务「**② 编译并运行当前文件**」，然后在底部终端里敲数字回车
（`⌘⇧B` 只会编译，不会给你机会输入）。

### 5.5 📖 选读：`scanf` 的一个隐藏麻烦（缓冲区残留）

这段现在看不懂完全正常，**先知道有这么回事**，等第 4 课学了 `if` 再回来看：

```c
int n = 0;
char c = 0;
scanf("%d", &n);      /* 你输入 "5" 然后回车 */
scanf("%c", &c);      /* 你以为它会等你输入字符，其实它读到了那个"回车"！ */
```

原因：你敲的回车（换行符）会**留在输入缓冲区**里，下一个 `scanf` 会立刻把它吃掉。
解法（两种都常见）：

```c
scanf(" %c", &c);        /* ⭐ 最常用：%c 前面加一个空格，意思是"吃掉前面的空白字符" */
```

或者

```c
getchar();               /* 手动吃掉那个换行 */
scanf("%c", &c);
```

**注意**：`%d`、`%f` 这些**自动跳过**空白字符，所以只有 `%c` 和 `%s` 才会遇到这个坑。

## 6. 综合实例：成绩单 + 一个大陷阱

[examples/05_average.c](examples/05_average.c)：读入三门成绩，输出总分和平均分。
我用 `90 81 85` 作输入，**本机真实输出**：

```text
请输入三门课的成绩（用空格隔开，例如 90 81 85）：

成绩单
  第 1 门： 90 分
  第 2 门： 81 分
  第 3 门： 85 分
  ------------------
  总分  ：256 分
  平均分（错误写法）：85.00 分   ← sum / 3 先按整数算，小数已经被丢掉
  平均分（正确写法）：85.33 分   ← sum / 3.0，运算按小数进行
```

**看到差别了吗？`85.00` vs `85.33`。** 这就是本课最值钱的一课：

### 整数除法陷阱

```c
int sum = 256;
printf("%.2f", sum / 3);      /* ❌ 85.00 —— 256/3 先按整数算成 85，小数被砍掉 */
printf("%.2f", sum / 3.0);    /* ✅ 85.33 —— 有一个是小数，运算就按小数进行 */
```

| 规则 | **整数 ÷ 整数 = 整数**（小数部分**直接砍掉**，不四舍五入） |
| --- | --- |
| 例子 | `7 / 2` 是 `3`，不是 `3.5` |
| 解法 | 让参与运算的至少一边是小数：写成 `3.0`、`7.0 / 2` |
| 危害 | **编译器一句话都不说** —— 0 错误 0 警告，程序跑得欢，答案就是错的 |

**真实输出佐证**（就在同一个程序里）：

```text
陷阱验证：
  7 / 2     = 3      ← 整数运算，小数被砍掉
  7 / 2.0   = 3.50    ← 有一个是小数，结果就是小数
  7.0 / 2   = 3.50    ← 反过来也一样
```

> 🎯 **第 2 课最重要的一句话**
> **"编译通过"和"结果正确"是两件完全不同的事。**
> 第 1 课你在练第一件；从第 2 课起，你必须开始在意第二件。
> 求平均分、求百分比、求比例 —— 这三个场景，永远先想一遍"这里会不会变成整数除法"。

## 8. 小测验（先自己想，再展开答案）

**Q1.** 为什么 `printf("%d\n", a)` 不用 `&`，而 `scanf("%d", &a)` 必须要 `&`？用你自己的话说。

**Q2.** `int x = 7, y = 2; printf("%d\n", x / y);` 输出什么？想让结果变成 `3.50`，怎么改？

**Q3.** `printf("[%5d]\n", 42);` 屏幕上会出现什么？（包括空格）

**Q4.** 想让这张表的两列都对齐，下面哪一行写法最专业？
```c
printf("Alex    95\n");
printf("Alex\t95\n");
printf("%-8s%4d\n", "Alex", 95);
```

**Q5.** 我要用 `scanf` 读入一个 `double` 变量，格式符该写 `%f` 还是 `%lf`？为什么？

**Q6.** `char c = 'A'; printf("%d\n", c);` 输出什么？

<details>
<summary>👉 点这里展开答案与解析</summary>

**A1.** `printf` 是"**把变量的值拿出来**给别人看"，只要知道 `a` 的值就够了，所以给 `a`；
`scanf` 是"**把数据送进变量里**"，必须知道这个变量在内存的**哪个位置**，所以要给地址 `&a`。
一句话：**"取出来看" vs "送进去存"。**

**A2.** 输出 **`3`**。
因为 `x` 和 `y` 都是 `int`，**整数除整数结果还是整数，小数被直接砍掉**（不是四舍五入）。
想得到 `3.50`，让一边变成小数：

```c
printf("%.2f\n", x / 2.0);      /* 或 (double)x / y */
```

**A3.** `[   42]`
`%5d` 表示"占 5 格、右对齐"，`42` 只占 2 格，所以前面补 **3 个空格**。
（方括号只是我加的边界标记，方便你看清格子在哪。）

**A4.** **第 3 行** `printf("%-8s%4d\n", "Alex", 95);`
- 第 1 行手数空格：内容一变就要重数；
- 第 2 行 `\t`：第 1 课批改里实测过，`\t` 是按 8 列制表位跳的，**内容一变长就崩**；
- 第 3 行宽度控制：**内容变长会自动适应**（只要不超出给定宽度），是专业做法。

**A5.** **`%lf`。**
`%f` 对应 4 字节的 `float`，而 `double` 是 8 字节，长度不匹配会导致**数据根本没读进去**。
我实测过：用 `scanf("%f", &d)` 输入 `3.14`，结果 `d` 还是 `0.000000`。
**注意区别**：`printf` 里 `%f` 就能打 `double`（输入输出规则不一样！）。

**A6.** 输出 **`65`**。
因为 `char` 里存的本来就是数字（ASCII 编码），换一个格式符就换一种"看它的方式"：
`%c` 看成字符 → `A`；`%d` 看成整数 → `65`。
顺带记住：`'a'` 是 97，`'0'`（字符零）是 48。

</details>
